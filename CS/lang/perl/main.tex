    \unsect{Perl}
    \begin{itemize}
        \item \textbf{Practical extraction and reporting language (perl)}: Perl is a high-level, general-purpose, interpreted, dynamic programming language. Though Perl is not officially an acronym, \textbf{Practical Extraction and Reporting Language} is commonly used as a \textbf{backronym}.
        \item \textbf{use version pragma}: The use VERSION pragma in Perl enforces a minimum version required to run a script and automatically enables modern language features 
            \bigbreak \noindent 
            You should place this declaration at the very top of your file. Modern Perl code uses the vX.Y v-string format rather than old-style decimals:
            \begin{perlcode}
                use v5.36
            \end{perlcode}
            \bigbreak \noindent 
            Versions v5.10 and higher automatically activate the feature pragma for that release. For example, use v5.36; is equivalent to loading use feature ':5.36';. This gives you immediate access to built-in keywords like say, state, and updated signatures without typing extra code
            \bigbreak \noindent 
            Declaring use v5.11 or higher automatically turns on the strict pragma (use strict;) lexically across your file.
            \bigbreak \noindent 
            Declaring use v5.35 or higher automatically turns on the warnings pragma (use warnings;
        \item \textbf{use feature}: In Perl, the use feature pragma allows you to enable newer syntactic features and capabilities without breaking backward compatibility for older programs. Because it is a lexical pragma, any feature you enable is only active from the line it is declared until the end of its enclosing code block.
            \begin{itemize}
                \item \textbf{Individual Features:} Pass a list of feature names to the pragma.
                    \bigbreak \noindent 
                    \begin{perlcode}
                        use feature 'say';                        
                        say "Hello, world!"; # Appends a newline
                    \end{perlcode}
                \item \textbf{Feature bundles}: Load all features mad available in a specific Perl release by prefixing the version with a colon
                    \bigbreak \noindent 
                    \begin{perlcode}
                        use feature ':5.36'
                    \end{perlcode}
                \item \textbf{Implicit loading}: Requiring a minimum Perl version automatically enables the feature bundle for that version
            \end{itemize}
        \item \textbf{Command Line Execution}:  Use the -E flag instead of -e to quickly test code snippets with all features enabled for your current Perl version.
            \bigbreak \noindent 
            \begin{perlcode}
                perl -E 'say "Fast one-liner testing'
            \end{perlcode}
        \item \textbf{Using the diagnostics pragma}: Another pragma that you may find useful is the diagnostics pragma. This translates the normally terse diagnostics emitted from the perl compiler and the perl interpreter into much more useful ones
            \bigbreak \noindent 
            \begin{perlcode}
                use diagnostics;
            \end{perlcode}
            \bigbreak \noindent 
            The diagnostics pragma makes your warnings much more verbose, and it slows the start-up time of your script considerably. You should remove it before putting your code into production.
        \item \textbf{Memory management}: Perl 5 memory management is primarily based on reference counting, with a runtime that manages Perl values such as scalars, arrays, hashes, and objects for you.
        \item \textbf{Compiled?}:  Every time you execute a script, the Perl interpreter first compiles your source code into an internal bytecode before immediately running it. Because this compilation happens seamlessly in the background right before execution, Perl is often colloquially categorized as an interpreted scripting language.
            \begin{itemize}
                \item \textbf{Compilation Phase:} The engine parses your source code. It converts text into optimized opcode structures.
                \item \textbf{Execution Phase:} The internal Perl virtual machine runs that bytecode.
            \end{itemize}
        \item \textbf{Pass by reference}: Arguments in Perl are passed by reference implicitly under the hood. Unlike many modern languages that default to copying a value, Perl passes the actual underlying variable into the function using a special array called @\_.
            \bigbreak \noindent 
            When you call chomp(\$text), Perl doesn't copy the string "Hello\string\n". Instead, it places an alias of the \$text variable into the first slot of the argument array (\$\_[0]).
            \bigbreak \noindent 
            Because chomp is an internal C function built into the Perl core, it modifies \$\_[0] directly. Since \$\_[0] points to the exact same memory location as your \$text variable, your original variable changes.



    \end{itemize}

    \unsect{Comments}
    \begin{itemize}
        \item \textbf{Standard comments}: Uses a hashtag
            \bigbreak \noindent 
            \begin{perlcode}
                # Comment
            \end{perlcode}
        \item \textbf{Block comments}: We can also use Plain Old Documentation (POD)
            \bigbreak \noindent 
            \begin{perlcode}
                =begin comment
                ...
                ...
                =end comment

                =cut
            \end{perlcode}
            \bigbreak \noindent 
            =cut resumes Perl code execution. "Stop ignoring this text; switch back to executable Perl code."
            \bigbreak \noindent 
            =end comment closes a =begin comment region. "This specific comment block is done, but continue treating subsequent text as documentation."
        \item \textbf{\_\_END\_\_}: You can signal to Perl the end of your program by using the special \_\_END\_\_ tag. Anything below \_\_END\_\_ will be ignored by Perl.
            \bigbreak \noindent 
            \begin{perlcode}
                #!/usr/bin/perl

                print "Hello world";

                __END__
            \end{perlcode}

    \end{itemize}

    \unsect{Variables}
    \begin{itemize}
        \item \textbf{Pragmatic information (pragma)}: A code pragma (short for "pragmatic information") is a special instruction or command embedded in source code. It tells a compiler, interpreter, or assembler how to process the program, but it does not change the actual logic or output of the software itself.
        \item \textbf{Note about variables}: In Perl, it is not necessary to declare your variables before you begin. You can summon a variable into existence simply by using it, and it will be globally available to any routine in your program. If you’re used to programming in C or any of a number of other languages, this may seem odd and even dangerous to you. This is indeed the case. That’s why you want to use the strict pragma.
        \item \textbf{Variable sigils (prefixes)}: In Perl, variable prefixes are called sigils, and they immediately identify the data type of the variable.
            \begin{itemize}
                \item \$ used for scalars
                \item @ used for arrays
                \item \% used for hashes. A hash is an unordered collection of key-value pairs (associative arrays).
            \end{itemize}
        \item \textbf{my, our, and state}: In Perl, my declares a truly private lexical variable, state creates a persistent static variable that initializes only once, and our creates a temporary shortcut to a global package variable
            \bigbreak \noindent 
            A lexical variable is a variable that is available only within a specific, textually defined part of a program, such as a function, a block, or a file.
        \item \textbf{The strict pragma}: Once we use the strict pragma, we have to explicitly declare new variables with scope keywords my, our, or state.
            \bigbreak \noindent 
            \begin{perlcode}
                #!/usr/bin/perl -w
                use strict;

                my $x = 50; # Okay
                $y = 100; # Bad
            \end{perlcode}
        \item \textbf{Variables with name $a$ or $b$}: \$a and \$b are special variables in Perl. they are implicitly used by Perl's built-in sort function. Inside the sort block, Perl automatically places the two values being compared into \$a and \$b. Consequently, strict 'vars' specifically permits \$a and \$b without requiring my
        \item \textbf{Scalars}: A scalar is a single item of data
            \bigbreak \noindent 
            \begin{perlcode}
                my $name = "Arthur";
                my $whoami = ’Just Another Perl Hacker’;
                my $meaning_of_life = 42;
                my $number_less_than_1 = 0.000001;
                my $very_large_number = 3.27e17; # 3.27 by 10 to the power of 17
            \end{perlcode}
            \bigbreak \noindent 
            A scalar can be text of any length, and numbers of any precision (machine dependent, of course). Perl doesn’t need us to tell it what type of data we’re going to put into the scalar. In fact, Perl doesn’t care if the type of data in the scalar changes throughout your program. Perl magically converts between them when it needs to
        \item \textbf{Single vs double quotes}: In Perl, quotes are required to distinguish strings from the language’s reserved words or other expressions. Either type of quote can be used, but there is one important difference: double quotes can include other variable names inside them, and those variables will then be interpolated
            \bigbreak \noindent 
            \begin{perlcode}
                my $x = 50;
                print "$x";
            \end{perlcode}
        \item \textbf{Special characters}: Special characters, such as the \textbackslash n newline character, are only available within double quotes. Single quotes will fail to expand these special characters just as they fail to expand variable names
        \item \textbf{String concatenation}: Uses the dot notation
            \bigbreak \noindent 
            \begin{perlcode}
                print "Hello, " . "World!";
            \end{perlcode}
        \item \textbf{Bash style interpolation}:
            \bigbreak \noindent 
            \begin{perlcode}
                my $x = "Hello";
                print "${x}, World";
            \end{perlcode}
        \item \textbf{References / dereferencing}: 
            \bigbreak \noindent 
            \begin{perlcode}
            my $x = 10;
            my $y = \$x; # Creates a reference

            $$y = 25; # $$ Dereferences
            \end{perlcode}
            \begin{itemize}
                \item \textbackslash \$scalar
                \item \textbackslash @array
                \item \textbackslash \%hash
                \item \textbackslash \&function
            \end{itemize}
        \item \textbf{Typeglobs}: In Perl, a typeglob (represented by the asterisk * sigil) is an internal data type that holds a complete symbol table entry for a given identifier.
            \bigbreak \noindent 
            Because Perl allows you to use the exact same name for different variable types simultaneously (e.g., \$apple, @apple, \%apple, and sub apple), Perl uses a typeglob to bundle all of these variables into a single slot in the package's symbol table. You can visualize a typeglob as a structure containing separate internal pointers for each variable type
            \begin{center}
                \begin{tabularx}{\textwidth}{@{}lXX@{}}
                    \toprule
                    \textbf{Slot / Prefix} \textbf{Data Type} \textbf{Example} \\
                    \midrule
                    \$ &Scalar &\$apple\\[2ex]
                    @ &Array &@apple\\[2ex]
                    \% &Hash &\%apple\\[2ex]
                    \& &Subroutine / Code &apple()\\[2ex]
                    * &IO / Filehandle &APPLE \\
                    \bottomrule
                \end{tabularx}
            \end{center}
        \item \textbf{Typeglob uses}: Assigning one typeglob to another maps all variables of that name to the new name.
            \bigbreak \noindent 
            \begin{perlcode}
                *foo = *bar;
                # Now $foo is an alias for $bar, @foo for @bar, %foo for %bar, etc.
            \end{perlcode}
            \bigbreak \noindent 
            By assigning a reference to a typeglob slot, you can alias just one specific type
            \bigbreak \noindent 
            \begin{perlcode}
                *foo = \$bar; 
                # Only $foo and $bar are now the same variable. 
                # @foo and @bar remain completely separate.
            \end{perlcode}
        \item \textbf{Creating constants}
            \bigbreak \noindent 
            \begin{perlcode}
            my $PI = \3.14;
            \end{perlcode}
            \bigbreak \noindent 
            creates a reference to a read-only scalar constant containing the value 3.14.
            \bigbreak \noindent 
            \begin{perlcode}
            print $$PI;
            $$PI = 10; # Error
            \end{perlcode}

        \item \textbf{Creating constants with typeglob}: You can generate read-only variables by assigning a reference to a constant value inside a typeglob.
            \bigbreak \noindent 
            \begin{perlcode}
                *PI = \3.14159;
                $PI = 4; # Compiles to a run-time error: "Modification of a read-only value..."
            \end{perlcode}
        \item \textbf{Legacy filehandles}: In older Perl code, typeglobs or references to typeglobs (\textbackslash *FH) were required to pass filehandles into subroutines. Modern Perl handles this automatically via lexical scalar filehandles (open my \$fh, ...).
        \item \textbf{Slots in a typeglob}: Use
            \bigbreak \noindent 
            \begin{perlcode}
            *NAME{SLOT}
            \end{perlcode}
            \bigbreak \noindent 
            Common slot names include:
            \bigbreak \noindent 
            \begin{perlcode}
                SCALAR
                ARRAY
                HASH
                CODE
                IO
                FORMAT
                GLOB
            \end{perlcode}
        \item \textbf{Inspecting prototypes}: If you need to retrieve or inspect a prototype programmatically from an existing function, you can use the built-in prototype function:
            \bigbreak \noindent 
            \begin{perlcode}
            my $proto = prototype('my_subroutine_name');
            \end{perlcode}
        \item \textbf{Variable attributes}: In Perl, a variable attribute is extra metadata attached to a variable declaration. It can change how the variable is created, stored, or handled. Attributes appear after the declared variable:
            \bigbreak \noindent 
            \begin{perlcode}
                my $scalar :Attribute;
                my @array  :Attribute;
                my %hash   :Attribute;
            \end{perlcode}
            \bigbreak \noindent 
            An attribute can optionally receive an argument:
            \bigbreak \noindent 
            \begin{perlcode}
            my $value :Attribute(argument);
            \end{perlcode}
            \bigbreak \noindent 
            Multiple attributes can be attached to one variable:
            \bigbreak \noindent 
            \begin{perlcode}
                my $value :First :Second(argument);
            \end{perlcode}
            \bigbreak \noindent 
            Whether an attribute is valid and what it does depends on the module or package that implements it.
        \item \textbf{MODIFY\_*\_ATTRIBUTES hooks}: This is Perl’s fundamental, low-level mechanism. A package defines a special method corresponding to the variable’s underlying reference type:
            \bigbreak \noindent 
            \begin{perlcode}
                MODIFY_SCALAR_ATTRIBUTES
                MODIFY_ARRAY_ATTRIBUTES
                MODIFY_HASH_ATTRIBUTES
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                sub MODIFY_SCALAR_ATTRIBUTES {
                    my ($package, $variable_ref, @attributes) = @_;

                    my @unrecognized;

                    for my $attribute (@attributes) {
                        if ($attribute eq 'Positive') {
                            print "Applying :Positive\n";
                        }
                        else {
                            push @unrecognized, $attribute;
                        }
                    }

                    return @unrecognized;
                }

                my $number :Positive = 10;
            \end{perlcode}
            \bigbreak \noindent 
            When Perl compiles the declaration, it approximately performs:
            \bigbreak \noindent 
            \begin{perlcode}
                Example->MODIFY_SCALAR_ATTRIBUTES(
                    \$number,
                    'Positive'
                );
            \end{perlcode}
            \bigbreak \noindent 
            The handler must return every attribute it did not recognize. If it returns an attribute, Perl reports an error
            \bigbreak \noindent 
            A handler that accepts everything can return an empty list
        \item \textbf{Fetch hooks}: A package may also define a corresponding fetch hook:
            \bigbreak \noindent 
            \begin{perlcode}
                FETCH_SCALAR_ATTRIBUTES
                FETCH_ARRAY_ATTRIBUTES
                FETCH_HASH_ATTRIBUTES
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                sub FETCH_SCALAR_ATTRIBUTES {
                    my ($package, $variable_ref) = @_;

                    return 'Positive';
                }
            \end{perlcode}
            \bigbreak \noindent 
            The attributes module can then retrieve them:
            \bigbreak \noindent 
            \begin{perlcode}
                use attributes;

                my @attrs = attributes::get(\$number);
            \end{perlcode}
        \item \textbf{Attribute::Handlers}: is a higher-level interface built around Perl’s attribute machinery. It lets you define a handler using attribute syntax instead of manually implementing each MODIFY\_*\_ATTRIBUTES method.
            \bigbreak \noindent 
            \begin{perlcode}
            package Example;

            use strict;
            use warnings;
            use Attribute::Handlers;

            sub Positive :ATTR(SCALAR) {
                my (
                    $package,
                    $symbol,
                    $variable_ref,
                    $attribute,
                    $data,
                    $phase,
                    $filename,
                    $line
                ) = @_;

                print "Applied :Positive at $filename line $line\n";
            }

            my $number :Positive = 10;
            \end{perlcode}
            \bigbreak \noindent 
            You can allow several target types
            \bigbreak \noindent 
            \begin{perlcode}
                sub Tracked :ATTR(SCALAR, ARRAY, HASH) {
                    ...
                }
            \end{perlcode}

    \end{itemize}

    \unsect{Arrays}
    \begin{itemize}
        \item \textbf{Creating arrays}: Arrays are initialised by creating a comma separated list of values:
            \bigbreak \noindent 
            \begin{perlcode}
                my @arr = (1,2,3);
            \end{perlcode}
            \bigbreak \noindent 
            Perl’s arrays, like those in many other languages, are indexed from zero
        \item \textbf{Accessing}: As you would expect
            \bigbreak \noindent 
            \begin{perlcode}
                print $fruits[0];
            \end{perlcode}
            \bigbreak \noindent 
            We use the dollar sign here because the indexing produces a scalar.
        \item \textbf{Slicing}: If we wanted to only deal with a portion of the array, we use what we call an array slice. These are written as follows:
            \bigbreak \noindent 
            \begin{perlcode}
                @arr # entire array
                @arr[1,3]
                @arr[0..2]
            \end{perlcode}
        \item \textbf{Negative indexing}:
            \bigbreak \noindent 
            \begin{perlcode}
                print $arr[-1] # 3
            \end{perlcode}
        \item \textbf{Array size}: 
            \bigbreak \noindent 
            \begin{perlcode}
                print $#arr + 1;
            \end{perlcode}
            \bigbreak \noindent 
            Note that \texttt{\$\#arr} gets the index of the last element. We can also use
            \bigbreak \noindent 
            \begin{perlcode}
                my $size = @arr;
                print my $size = @arr;
            \end{perlcode}
        \item \textbf{qw// (quote words)}: It takes whitespace separated words and turns them into a list
            \bigbreak \noindent 
            \begin{perlcode}
                my @arr = qw/hello , world/
            \end{perlcode}
            \bigbreak \noindent 
            Your list can stretch over multiple lines, and your delimiter doesn’t need to be a slash. Whatever punctuation character that you place after the qw becomes the delimiter. So if you prefer parentheses over slashes, that’s no problem at all
        \item \textbf{Printing out arrays}
            \bigbreak \noindent 
            \begin{perlcode}
                my @arr = (1,2,3);
                print @arr;
                print join(", ", @arr);
                print "@arr"
            \end{perlcode}
            \bigbreak \noindent 
            The first method takes advantage of the fact that print takes a list of arguments to print and prints them out sequentially. The second uses join() which joins an array or list together by separating each element with the first argument. The third option uses double quote interpolation and a little bit of Perl magic to pick which character(s) to separate the words with.
        \item \textbf{Context}: There’s a term you’ve heard used just recently but which hasn’t been explained: context. Context refers to how an expression or variable is evaluated in Perl. The two main contexts are:
            \begin{itemize}
                \item Scalar context
                \item List context
            \end{itemize}
            Scalar variables are always evaluated in scalar context, however arrays and hashes can be evaluated in both scalar contexts (when we treat them as scalars) and list contexts (when we treat them as arrays and hashes).Scalar variables are always evaluated in scalar context, however arrays and hashes can be evaluated in both scalar contexts (when we treat them as scalars) and list contexts (when we treat them as arrays and hashes).
            \bigbreak \noindent 
            Many things in Perl are very specific about which context they require and will force lists into scalar context when required. For example the + (plus or addition) operator expects that its two arguments will be scalars. Hence:
            \bigbreak \noindent 
            \begin{perlcode}
                my @a = (1,2,3);
                my @b = (4,5,6,7);
                print @a + @b;
            \end{perlcode}
            \bigbreak \noindent 
            will print 7. There’s also a third type of context, the null context, where the result of an operation is just thrown away. This usually isn’t discussed, because by its very definition we don’t care about what result is returned
        \item \textbf{Lists}: A list is an unnamed array.
            \bigbreak \noindent 
            \begin{perlcode}
            print ("Hello", ",", " ", "World", "\n");
            \end{perlcode}
            \bigbreak \noindent 
            If you come across something that wants a LIST, you can either give it the elements of list as in the first example above, or you can pass it an array by name. If you come across something that wants an ARRAY, you have to actually give it the name of an array. Examples of functions which insist on wanting an ARRAY are push() and pop(), which can be used for adding and removing elements from the end of an array
        \item \textbf{Anonymous array reference}: 
            \bigbreak \noindent 
            \begin{perlcode}
                my $ref = [1,2,3];
            \end{perlcode}
            \bigbreak \noindent 
            The = [ ... ] syntax is used to create and assign an anonymous array reference. Square brackets [ ] create a memory reference to an array that has no name. This reference is a single scalar value, meaning it is stored in a standard scalar variable (\$).
        \item \textbf{Multiple dimensional arrays}:
            \bigbreak \noindent 
            \begin{perlcode}
                my $matrix = [
                    [1,2,3],
                    [4,5,6],
                    [7,8,9]
                ];
            \end{perlcode}
            \bigbreak \noindent 
            Passing a reference to a subroutine avoids flattening your data structure and is much faster for large lists because Perl only copies the single memory address rather than the entire list.
        \item \textbf{Dereferencing}: 
            \bigbreak \noindent 
            \begin{perlcode}
            print $array_ref->[0]; # Outputs: apple

            # Loop through all elements
            for my $item (@$array_ref) {
                print "$item\n";
            }
            \end{perlcode}
            \bigbreak \noindent 
            The syntax
            \bigbreak \noindent 
            \begin{perlcode}
                @{$array_ref}
            \end{perlcode}
            \bigbreak \noindent 
            is used to dereference an array reference.


    \end{itemize}

    \unsect{Hashes}
    \begin{itemize}
        \item \textbf{Hashes}: A hash is a two-dimensional array which contains keys and values, they’re sometimes called "associative arrays", or "lookup tables". Instead of looking up items in a hash by an array index, you can look up values by their keys.        
            \bigbreak \noindent 
            Hashes are initialised in exactly the same way as arrays, with a comma separated list of values:
            \bigbreak \noindent 
            \begin{perlcode}
            my %monthdays = ("January", 31, "February", 28, "March", 31, ...);
            \end{perlcode}
            \bigbreak \noindent 
            Or,
            \bigbreak \noindent 
            \begin{perlcode}
                my %monthdays = (
                    "January" => 31,
                    "February" => 28,
                    "March" => 31,
                    ...
                );
            \end{perlcode}
            \bigbreak \noindent 
            The => operator is syntactically the same as the comma, but is used to distinguish hashes more easily from normal arrays. It’s pronounced "fat comma", or less often "fat arrow". It does have one difference, you don’t need to put quotes around a bare word immediately before the => operator as these are always treated as strings:
        \item \textbf{Reading hash values}: 
            \bigbreak \noindent 
            \begin{perlcode}
            print $monthdays{"January"}; # prints 31
            \end{perlcode}
            \bigbreak \noindent 
            Bare words inside the braces of the hash-lookup will be interpreted in Perl as strings, so usually you can drop the quotes:
        \item \textbf{Creating hash elements}: You can also create elements in a hash on the fly:
            \bigbreak \noindent 
            \begin{perlcode}
                my %monthdays = ();
                $monthdays{"January"} = 31;
                $monthdays{February} = 28;
                ...
            \end{perlcode}
        \item \textbf{Changing hash values}: To change a value in a hash, just assign the new value to your key:
            \bigbreak \noindent 
            \begin{perlcode}
            $pizza_prices{small} = ’$6.00’; # Small pizza prices have gone up
            \end{perlcode}
        \item \textbf{Deleting hash values}: Use the delete function
            \bigbreak \noindent 
            \begin{perlcode}
            delete($pizza_prices{medium}); # No medium pizzas anymore.
            \end{perlcode}
        \item \textbf{Finding out the size of a hash}: Strictly speaking there is no equivalent to using an array in a scalar context to get the size of a hash. If you take a hash in a scalar context you get back the number of buckets used in the hash, or zero if it is empty. This is only really useful to determine whether or not there are any items in the hash, not how many.
            \bigbreak \noindent 
            If you want to know the size of a hash, the number of key-value pairs, you can use the keys function in a scalar context. The keys function returns a list of all the keys in the hash.
            \bigbreak \noindent 
            \begin{perlcode}
                my $size = keys %monthdays;
                print $size; 
            \end{perlcode}

    \end{itemize}

    \unsect{Special variables}
    \begin{itemize}
        \item \textbf{Intro}: Perl has many special variables. These are used to set or retrieve certain values which affect the way your program runs. For instance, you can set a special variable to turn interpreter warnings on and off (\$$\land$W), or read a special variable to find out the command line arguments passed to your script (@ARGV). 
        \item \textbf{\$\_}: Represents the current thing that your Perl script’s working with --- often a line of text or an element of a list or hash. It can be set explicitly, or it can be set implicitly by certain looping constructs (which we’ll look at later).

    \unsect{Constructs}
    \begin{itemize}
        \item \textbf{If}
            \bigbreak \noindent 
            \begin{perlcode}
                if (cond) {
                    ...
                }

                elsif (cond) {
                    ...
                }

                else {
                    ...
                }
            \end{perlcode}
        \item \textbf{Unless}: inverse of an if
            \bigbreak \noindent 
            \begin{perlcode}
                unless (cond) {
                    ...
                }
            \end{perlcode}
            \bigbreak \noindent 
            Note that the brackets are required, and there is no \texttt{elsunless}.
        \item \textbf{Shorthand}: If if or unless require a single statement, we can put the statement before the check
            \bigbreak \noindent 
            \begin{perlcode}
            print "Hello" if 1;
            \end{perlcode}
        \item \textbf{Existence and definitiveness}: To find out if something is defined, use Perl’s defined function. The defined function is necessary to distinguish between a value that is false because it is undefined and a value that is false but defined, such as 0 (zero) or "" (the empty string).
            \bigbreak \noindent 
            \begin{perlcode}
                my $skippy; # $skippy is undefined and false
                $skippy = "bush kangaroo"; # true and defined
                print "true" if $skippy; # prints true
                print "defined" if defined($skippy); # prints defined

                my $udef = undef;
                print "defined" if defined($udef); # does not print
                print "undefined" if not defined($udef); # prints undefined
            \end{perlcode}
        \item \textbf{undef}: When you pass a variable or expression to it, undef behaves as a function that un-defines the variable and frees its memory. The expression must be an lvalue
            \bigbreak \noindent 
            \begin{cppcode}
            undef $scalar;       # Resets a scalar to the undefined state
            \end{cppcode}
            \bigbreak \noindent 
            When used on its own without any arguments, it simply returns the undefined value.
            \bigbreak \noindent 
            \begin{perlcode}
            my $name = undef;    # Explicitly assigning the undefined value
            \end{perlcode}
        \item \textbf{While}: 
            \bigbreak \noindent 
            \begin{perlcode}
                while (cond) {
                    ...
                }
            \end{perlcode}
        \item \textbf{Until}: The opposite of a while
            \bigbreak \noindent 
            \begin{perlcode}
                until (cond) {
                    ...
                }
            \end{perlcode}
        \item \textbf{Shorthand while / unless}: Similiar to if and unless,
            \bigbreak \noindent 
            \begin{perlcode}
            print "Hello" while 1;
            print "Hello" until 0;
            \end{perlcode}
        \item \textbf{For}: Identical to C
            \bigbreak \noindent 
            \begin{perlcode}
            for (my $i = 0; $i < $n; ++$i)
            \end{perlcode}
        \item \textbf{Foreach}:
            \bigbreak \noindent 
            \begin{perlcode}
                foreach(@arr) {
                    print "$_\n";
                }

                print "${_}\n" foreach(@arr);
            \end{perlcode}
            \bigbreak \noindent 
            \textbf{Note:} When in a foreach loop, the variable representing the current element \textbf{is} the current element, not a copy of it.
        \item \textbf{Foreach range syntax}:
            \bigbreak \noindent 
            \begin{perlcode}
            print "${_}" foreach (1..10) 
            \end{perlcode}
        \item \textbf{For / foreach and variable creation}
            \bigbreak \noindent 
            \begin{perlcode}
                for my $i (0..10) { ... }
                foreach my $i ((1,2,3)) {...}
            \end{perlcode}
        \item \textbf{Note about for and foreach}: In Perl, you can iterate through an array using the for loop (or foreach loop). Perl treats for and foreach as completely interchangeable synonyms.
            \bigbreak \noindent 
            \begin{perlcode}
            my @arr = qw(1 2 3);
            print "$_\n" for @arr;
            \end{perlcode}
        \item \textbf{Postfix for}: In Perl, the postfix for modifier (also known as a statement modifier) allows you to place a loop after a single statement
            \bigbreak \noindent 
            \begin{perlcode}
            STATEMENT for LIST;
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
            $_ *= 2 for @nums
            \end{perlcode}
        \item \textbf{= do {...}}: 
            \bigbreak \noindent 
            \begin{perlcode}
            my $variable = do { ... };
            \end{perlcode}
            \bigbreak \noindent 
            executes a block of code and returns the value of the last statement evaluated inside that block
        \item \textbf{eval BLOCK}: 
            \bigbreak \noindent 
            \begin{perlcode}
                eval {...}
            \end{perlcode}
            \bigbreak \noindent 
            acts like a try-catch block.
            \bigbreak \noindent 
            \begin{perlcode}
                # Example of trapping a division by zero error
                eval {
                    my $result = 10 / 0;
                };

                if ($@) {
                    print "Error caught: $@";
                }
            \end{perlcode}
        \item \textbf{eval EXPR}: This form compiles code string text dynamically
            \bigbreak \noindent 
            \begin{perlcode}
                # Example of dynamically executing a string
                my $code = '$x = 5 + 5;';
                eval $code;
                print $x; # Outputs 10
            \end{perlcode}
        \item \textbf{Labeled blocks}: You can assign a name (called a label) to any code block by placing the name followed by a colon (:) right before the opening brace. This allows you to jump out of or control specific nested blocks using loop control statements like last, next, or redo.
            \bigbreak \noindent 
            Always write labels in ALL CAPS to ensure they stand out and never conflict with reserved Perl keywords.
            \bigbreak \noindent 
            \begin{perlcode}
                OUTER_LOOP: while ($x < 10) {
                    INNER_LOOP: while ($y < 10) {
                        if ($condition) {
                            # Exits BOTH loops completely, not just the inner one
                            last OUTER_LOOP; 
                        }
                        $y++;
                    }
                    $x++;
                }
            \end{perlcode}
            \begin{itemize}
                \item redo restarts the current iteration immediately.
                \item next skips to the next iteration 
                \item last exits the loop completely (like break in C/Java).
            \end{itemize}
        \item \textbf{BEGIN}: A BEGIN block in Perl is a special type of code block that runs as soon as it is parsed and compiled, before the rest of the surrounding program runs.
            \begin{itemize}
                \item \textbf{Timing:} It executes immediately during the compilation phase, even before the rest of the script or file is fully compiled.
                \item \textbf{Order:} Multiple BEGIN blocks run in the order they appear in your code.
                \item \textbf{Purpose:} Commonly used to load modules (use is implemented using BEGIN), define subroutines, or set up global configuration variables before other code compiles.
                \item \textbf{Automatic Deletion:} Once a BEGIN block has run, it is immediately deleted from memory for the rest of the program
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
                print "2. This runs during runtime.\n";

                BEGIN {
                    print "1. This runs first, during compilation.\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                1. This runs first, during compilation.
                2. This runs during runtime.
            \end{perlcode}
        \item \textbf{END}: END \{\} block in Perl runs code automatically just before the Perl interpreter exits the program.
            \begin{itemize}
                \item \textbf{Timing:} It runs as late as possible during program shutdown, acting like a destructor.
                \item \textbf{Order:} Multiple END blocks run in the reverse order of how they appear in your code.
                \item \textbf{Exceptions:} END blocks run even if the program exits using die(). They do not run if the program exits via exec or a hard operating system signal like SIGKILL.
                \item \textbf{Common Uses:} They are great for cleanup tasks, such as closing file handles, removing temporary files, or disconnecting from databases.
            \end{itemize}
        \item \textbf{\_\_DATA\_\_}: \_\_DATA\_\_ token tells the compiler that the compilation of executable code is finished. Everything written below this token is treated as data, which Perl automatically makes accessible to your program through a special, built-in filehandle named DATA.
            \bigbreak \noindent 
            \begin{perlcode}
                use strict;
                use warnings;

                # Loop through each line in the __DATA__ section
                while (my $line = <DATA>) {
                    chomp($line);
                    print "Processing line: $line\n";
                }

                __DATA__
                First line of data
                Second line of data
                Third line of data
            \end{perlcode}
        \item \textbf{Heredocs}: 
            \bigbreak \noindent 
            \begin{perlcode}
                # 1. Double-quoted (Interpolated)
                print <<"EOF";
                Hello, $name!
                This is a multi-line string.
                EOF
            \end{perlcode}
        \item \textbf{Backtick heredoc}: 
            \bigbreak \noindent 
            \begin{perlcode}
                my $output = <<`END_CMD`
                ls -la /tmp
                echo "---"
                df -h /
                echo "---"
                uptime
                END_CMD
            \end{perlcode}
            \bigbreak \noindent 
            That's a backtick heredoc. Everything between the markers executes as a shell command. The output comes back as a string. Multi-line shell scripts, captured in one clean shot.
        \item \textbf{Heredoc variants}:
            \begin{itemize}
                \item <<"TAG"         Interpolates variables
                \item <<'TAG'         No interpolation (literal)
                \item <<`TAG`         Executes as shell command
            \end{itemize}
        \item \textbf{Stacked heredocs}: 
            \bigbreak \noindent 
            \begin{perlcode}
                my ($sql, $html) = (<<'SQL', <<'HTML');
                SELECT name, email
                FROM users
                WHERE active = 1
                ORDER BY name
                SQL
                <;div class="results">;
                    <;h2>;Active Users<;/h2>;
                    <;ul id="user-list">;<;/ul>;
                <;/div>;
                HTML
            \end{perlcode}
        \item \textbf{goto}: Three forms
            \begin{perlcode}
            goto LABEL
            goto EXPR
            goto &NAME
            \end{perlcode}
            \bigbreak \noindent 
            \begin{itemize}
                \item \textbf{goto LABEL}: This form instantly jumps to the line marked with a specific label name followed by a colon (LABEL:).
                    \bigbreak \noindent 
                    You cannot use this to jump into a construct requiring initialization, such as a subroutine or a foreach loop. It also cannot be used to jump out of a block passed to sort.
                \item \textbf{goto EXPR}: This evaluates an expression at runtime to get a string, and then jumps to the label matching that string. This behaves like a computed goto found in languages like Fortran
                    \bigbreak \noindent 
                    \begin{perlcode}
                        my @targets = ("FOO", "BAR", "BAZ");
                        my $index = 1;

                        goto $targets[$index]; # Evaluates to "BAR" and jumps there

                        FOO: print "Hit FOO\n";
                        BAR: print "Hit BAR\n"; # Execution jumps here
                        BAZ: print "Hit BAZ\n";
                    \end{perlcode}
                \item \textbf{goto \&NAME}: This is a specialized, "highly magical" feature that doesn't carry the standard stigma of goto. Instead of jumping to a text label, it exits the current subroutine and immediately calls the new subroutine in its place.
                    \bigbreak \noindent 
                    The new subroutine completely inherits the argument stack (@\_) of the old subroutine. When the new subroutine finished executing, it returns control directly back to whoever called the first subroutine
                    \bigbreak \noindent 
                    \begin{perlcode}
                        sub first_sub {
                            print "Inside first_sub\n";
                            goto &second_sub; # Exits first_sub, replaces it with second_sub
                        }

                        sub second_sub {
                            print "Inside second_sub with arguments: @_\n";
                            # When this ends, control goes back to wherever first_sub() was called.
                        }

                        first_sub("Hello", "World");
                    \end{perlcode}
            \end{itemize}
        \item \textbf{CHECK \{ ... \}}:  A CHECK block runs after the Perl compiler finishes compiling your code, but before the program actually starts running.
            \bigbreak \noindent 
             Multiple CHECK blocks run in reverse order of how they appear in your file (last-defined runs first).
        \item \textbf{INIT \{ ... \}}: An INIT block runs right before the Perl runtime system begins executing your main program.
            \bigbreak \noindent 
            Just after compilation and any CHECK blocks finish, but right before the main script starts.
            \bigbreak \noindent 
            Multiple INIT blocks run in normal order (first-defined runs first).


    \end{itemize}

    \subsection{File IO}
    \begin{itemize}
        \item \textbf{Line input operator in list context}: 
            \bigbreak \noindent 
            \begin{perlcode}
                # reading lines from STDIN (or from files on the command line)
                while (<>) {
                    # Process the line of input in $_
                }

                # reading a single line of user input from STDIN
                my $input = <STDIN>;

                # reading all lines from STDIN into an array
                my @input = <STDIN>;
            \end{perlcode}
            \bigbreak \noindent 
            In scalar context, the line input operator yields the next line of the file referenced by the filehandle given.
            \bigbreak \noindent 
            In list context, the line input operator yields all remaining lines of the file referenced by the filehandle. (Be careful when using this as you may use up all your memory if the file is large).
        \item \textbf{Failure}: You should always check for failure of an open() statement:
            \bigbreak \noindent 
            \begin{perlcode}
                open(LOGFILE, "< /var/log/httpd/access.log")
                    or die "Can’t open /var/log/httpd/access.log: $!";
            \end{perlcode}
            \bigbreak \noindent 
            Attempting to read from or write to an unopened file may cause unexpected results.
        \item \textbf{The die function (die())}: die is a Perl function which takes an error message and terminates the program displaying that message to the user.
            \bigbreak \noindent 
            \$! is the special variable which contains the error message produced by the last system interaction.
            \bigbreak \noindent 
            Perl tries to be helpful when dying on errors and will append the appropriate filename and line number of your script to the end of the die message, with a newline. If you don’t want this behaviour, end the die message with a newline (\string\n) character.
            \bigbreak \noindent 
            \begin{perlcode}
                # The following provides an error with file and line-number:
                open(LOGFILE, "< $file") or die "Cannot open $file: $!";

                # Here the file and line-number are omitted.
                open(LOGFILE, "< $file") or die "Cannot open $file: $!\n";
            \end{perlcode}
        \item \textbf{Fatal}: An alternative to explicitly checking whether open and other functions succeeded is to use the Fatal module:
            \bigbreak \noindent 
            \begin{perlcode}
                use Fatal qw(open close);

                open(LOGFILE, "< $file");   # no need to check!

                close(LOGFILE);             # no need to check!
            \end{perlcode}
            \bigbreak \noindent 
            The Fatal module creates its own functions for the ones you have passed in, and tells Perl to use those instead. These throw an exception (die) if the original function returns a false value. Care should be taken when retro-actively using Fatal on existing programs. It changes the behaviour of the specified functions for the whole program, not just for your file.
        \item \textbf{Filehandles}: The first argument we pass to open is a filehandle. We can use this to have access to the file for the mode in which it was opened.
            \bigbreak \noindent 
            \begin{perlcode}
                # Open access.log for reading using LOGFILE as our filehandle
                open(LOGFILE, "<", "/var/log/httpd/access.log")
                    or die "Can’t open /var/log/httpd/access.log: $!";

                # use the filehandle in the <> line input operator to read the contents
                while (<LOGFILE>) {
                    print if /perltraining.com.au/;
                }
                close LOGFILE;

                # open a new logfile for appending
                open(SCRIPTLOG, ">>", "myscript.log") or die "Can’t open myscript.log: $!";

                # print() takes an optional filehandle argument - defaults to STDOUT
                print SCRIPTLOG "Opened logfile successfully.\n";

                close SCRIPTLOG;
            \end{perlcode}
            \bigbreak \noindent 
            Note that you should always close a filehandle when you’re finished with it (even though any open filehandles will be automatically closed when your script exits).
        \item \textbf{Scalar filehandles}: Under Perl version 5.6.0 and above, you can provide a scalar as the first argument to the open function. This means that your filehandles can have scope, and makes it easier to pass them to subroutines and put into structures such as hashes and arrays. Where possible it is a good idea to always use scalar filehandles.
            \bigbreak \noindent 
            \begin{perlcode}
                my $fh;
                open($fh,"<", "/path/to/file") or die $!;

                # We can also declare the variable inside the call to open
                open(my $out_fh, "> /path/to/other/file") or die $!;
            \end{perlcode}
            \bigbreak \noindent 
            In versions before 5.6.0 you can do the same thing by using the FileHandle module, but you need to declare your intentions first:
            \bigbreak \noindent 
            \begin{perlcode}
                use FileHandle;
                my $fh = FileHandle->new; # $fh is now a FileHandle object.
                open ($fh, "<", "/path/to/file") or die $!;
            \end{perlcode}
        \item \textbf{Changing file contents}:  When manipulating files, we may wish to change their contents. A flexible way of reading and writing a file is to import the file into an array, manipulate the array, then output each element again. It is important to ensure that should anything go wrong we don’t lose our original data. As a result,
            \bigbreak \noindent 
            it’s considered best-practice to write our data out to a temporary file and them move that over the input file after everything has been successful.
            \bigbreak \noindent 
            \begin{perlcode}
                # a program that reads in a file and writes the lines in sorted order.
                use File::Copy;

                open(my $infile, "<", "file.txt") or die "Can’t open file.txt for input: $!";
                my @lines = <$infile>; # Slurps all the lines into @lines.
                close $infile;

                @lines = sort @lines;

                # open temporary file to save our sorted data into
                open(my $outfile, ">", "file.txt.tmp") or die "Can’t open file.txt for output: $!";

                # use print’s ability to print lists
                print {$outfile} @lines;

                close $outfile;

                # we know that we were successful, so write over the original file
                move("file.txt.tmp", "file.txt") or die "Could not rename temp file: $!";
            \end{perlcode}
        \item \textbf{Secure temporary files}: In the above example we create our own temporary file using a predictable filename. This may cause our program to over-write a temporary file that’s currently in use, which is obviously a bad thing. To create and use unique temporary files we can use the File::Temp module:
            \bigbreak \noindent 
            \begin{perlcode}
            use File::Temp qw(tempfile);

            my ($tmp_fh, $tmp_name) = tempfile();

            # use print’s ability to print lists
            print {$tmp_fh} @lines;

            close $tmp_fh;

            move($tmp_name, "file.txt") or die "Could not rename $tmp_name: $!";
            \end{perlcode}
            \bigbreak \noindent 
            The File::Temp module can also be used to create in-memory temporary files if required.
        \item \textbf{Open a file for reading and writing (Read + write mode)}: Files can be opened for simultaneous read/write by putting a + in front of the > or < sign. +< is almost always preferable, as +> would overwrite the file before you had a chance to read from it.
            \begin{itemize}
                \item +< (Read + Write, No Truncation)
                    \begin{itemize}
                        \item \textbf{Behavior:} Opens an existing file for both reading and writing. It does not clear the file contents when opened. The file pointer starts at the beginning of the file.
                        \item \textbf{File status:} The file must already exist (or it fails depending on usage, though standard behavior expects an existing file).
                        \item \textbf{Use case:} When you want to read from a file, modify specific parts, or overwrite parts of it in place without losing the rest of the data.
                    \end{itemize}
                \item +> (Read + Write, Truncate/Clobber)
                    \begin{itemize}
                        \item \textbf{Behavior:} Opens a file for reading and writing, but deletes all existing contents (truncates the file to zero length) immediately when opened.
                        \item \textbf{File status:} Creates the file if it does not exist.
                        \item \textbf{Use case:} Rare; useful when you want a completely fresh scratchpad file that you can both write to and read back from during the same session.
                    \end{itemize}
            \end{itemize}
            +< puts you at the start of the file. Note that it won’t create a new file if the file you’re dealing with does not exist (you’ll just get an error that the file doesn’t exist). If you start writing before you’ve reached the end of the file, you will overwrite characters in that file (from that point). Even if you’re dealing with fixed-length records and think you know what you’re doing, this is often still a bad idea.
            \bigbreak \noindent 
            +>> initially puts you at the end of the file. It will create a new file if necessary and will not clobber an old one. It allows you to read at any point in the file, but all writes will always go to the end.
        \item \textbf{Buffering}: Since both print and readline (<>) are buffered, you should not use them for editing a file in-place. If you must do so, use the lower level functions such as sysseek(), syswrite() and sysread(). Perl also has a -i switch, for more useful in-place modification of files.
        \item \textbf{Opening pipes}: If the filename given to open() begins with a pipe symbol (|), the filename is interpreted as a command to which output is to be piped, and if the filename ends with a |, the filename is to be interpreted as a filename which pipes input to us.
            \bigbreak \noindent 
            you can pass a system command to open in Perl by using the pipe character (|). When you place a pipe at the very end or the very beginning of the command string, Perl treats it as a program to run rather than a file to read. This is known as a piped open.
            \bigbreak \noindent 
            \begin{perlcode}
            # Runs the Linux 'ls' command and lets you read the file list
            open(MY_PIPE, "ls -la |") or die "Failed: $!";

            # Sends text directly into the Linux 'mail' command to send an email
            open(MY_PIPE, "| mail -s 'Hello' user@example.com") or die "Failed: $!";
            \end{perlcode}
        \item \textbf{Safer pipes}
            \bigbreak \noindent 
            \begin{perlcode}
            # Pipe output to us
            open(my $pipe, "-|", "ls", "-la");

            # Pipe our input to sort
            open(my $pipe, "|-", "sort");
            \end{perlcode}
        \item \textbf{Piping input example}
            \bigbreak \noindent 
            \begin{perlcode}
                # Open our external sort command.
                open (my $sort_fh, "|sort") or die "Can’t open pipe: $!";

                # Our friends will be printed in sorted order.
                foreach my $friend (qw/Jacinta Damian Kirrily Paul/) {
                    # This does not print to stdout, gives the names to sort one at a time.
                    print {$sort_fh} "$friend\n";
                }

                # Closing the pipe handle causes sort to cease thus giving output
                close $sort_fh;
            \end{perlcode}
        \item \textbf{Piping output example}
            \bigbreak \noindent 
            \begin{perlcode}
            #!/usr/bin/perl -w
            # This program allows us to read a file from another machine
            # using secure shell. This is most useful if we can login without
            # a password (eg, established keys).
            use strict;

            # Process our command line arguments, and complain if we don’t
            # have both a host and filename.
            my ($host, $file) = @ARGV;
            unless ($host and $file) {
                die "Usage: $0 host filename\n";
            }

            open (SSH, "ssh $host cat $file |") or die "Can’t open pipe: $!";

            while(<SSH>) {
                # We can process the file in any way we like here.
                # In this particular case, we’ll simply print it to
                # our STDOUT.
                print;
            }
            \end{perlcode}
        \item \textbf{File locking}: File locking can be achieved using the flock() function. This can be used to guard against race conditions or other problems which occur when two (or more) processes want to access the same file at the same time.
            \bigbreak \noindent 
            flock is Perl’s portable file-locking mechanism, and works on most operating systems (and produces a fatal error on those which it does not). The locks set by flock are advisory only, which means that a process that chooses not to use flock can (and will) ignore any locks in place. flock can only lock entire files, not individual records. Depending upon your setup, flock may or may not work over NFS.
            \bigbreak \noindent 
            \begin{perlcode}
                # using flock
                use Fcntl ’:flock’; # import LOCK_* constants

                flock(FILEHANDLE, LOCK_EX); # exclusive (write) access
                flock(FILEHANDLE, LOCK_SH); # shared (read-only) access
            \end{perlcode}
            \bigbreak \noindent 
            As flock only works on filehandles, instead of filenames, you have to open the file first before you try to lock it. It’s important to make sure that you open the file for writing, if you intend to write to it, and that you don’t clobber the contents of the file when doing so. This is a good use of +<. Closing a locked file releases any locks the process holds upon it. This is good because it means that if your process exits unexpectedly all locks it held are released and other processes may then go forward with their locks.
            \bigbreak \noindent 
            \begin{perlcode}
                use Fcntl ’:flock’; # import LOCK_* constants

                # Open file for read and write
                open my $file_fh, "+<", $file or die "Failed to open $file: $!";

                # Lock the file for writing (exclusive lock) make sure it worked.
                flock($file_fh, LOCK_EX) or die "Failed to gain lock on $file: $!";

                # At this point we have exclusive access to the file.
                # Wipe previous process’ details
                truncate($file_fh, 0) or die "Failed to truncate $file: $!";

                # Write to the file, or perform other operations as needed here...
                print {$file_fh} $data;

                close $file_fh; # Closing the file releases the lock as well
            \end{perlcode}
            \bigbreak \noindent 
            flock will wait indefinitely until the lock is granted, however it can return early if interrupted by a signal or other event. It’s important to ensure that flock returns true to be sure that you have the lock you requested. It is possible to make flock non-blocking as follows:
            \bigbreak \noindent 
            \begin{perlcode}
                use Fcntl ’:flock’; # import LOCK_* constants

                flock(FILEHANDLE, LOCK_EX | LOCK_NB); # non-blocking exclusive lock
                flock(FILEHANDLE, LOCK_SH | LOCK_NB); # non-blocking shared lock
            \end{perlcode}
            \bigbreak \noindent 
            All attempts to get a non-blocking lock return immediately with either true for success (the lock was obtained) or false for failure (the lock was not obtained).
        \item \textbf{Handling binary data / read()}: If you are opening a file which contains binary data, you probably don’t want to read it in a line at a time using while (<>) \{ \}, as there’s no guarantee that there will be any line breaks in the data, and we’ll probably end up with very uneven chunks.
            \bigbreak \noindent 
            Instead, we can use read() to read a certain number of bytes from a file handle. However, before we do that, we should call the binmode() function on the filehandle, so that Perl knows that we’ll be dealing with a binary file. This means Perl won’t try to do any transformations of input based upon the operating system or locale where your program is running.
            \bigbreak \noindent 
            binmode() must be called on the filehandle before any corresponding file I/O. It’s best to call it immediately after you open the file.
            \bigbreak \noindent 
            read() takes the following arguments:
            \begin{itemize}
                \item The filehandle to read from
                \item The scalar to put the binary data into
                \item The number of bytes to read
                \item The byte offset to start from (defaults to 0)
            \end{itemize}

    \end{itemize}

    \subsection{Directory Interaction}
    \begin{itemize}
        \item \textbf{The globbing operator}: If the angle brackets have anything in them other than a filehandle or nothing, it will work as a globbing operator and whatever is between the angle brackets will be treated as a filename wildcard. For instance
            \bigbreak \noindent 
            \begin{perlcode}
            my @files = <*.txt>
            \end{perlcode}
            \bigbreak \noindent 
            The filename glob *.txt is matched against files in the current directory, then either they are returned as a list (in list context, as above) or one scalar at a time (in scalar context).
            \bigbreak \noindent 
            \begin{perlcode}
                while (my $filename = <*.txt>) {
                    open (my $in_fh, "<", $filename) or die ("Can’t open $filename: $!");

                    # Read from the file
                    close $in_fh;
                }
            \end{perlcode}
            \bigbreak \noindent 
            The glob() function behaves in a very similar manner to the angle bracket globbing operator.
            \bigbreak \noindent
            \begin{perlcode}
                my @files = glob("*.txt");
                foreach my $file (glob("*.txt")) {
                    # Process $file
                }
            \end{perlcode}
            \bigbreak \noindent 
            The glob() is considered much cleaner and better to use than the angle-brackets globbing operator.
            \bigbreak \noindent 
            When using glob, you can combine more than one pattern in order to get a wider selection of files. For example, to get all the .txt and .pl files you can write:
            \bigbreak \noindent 
            \begin{perlcode}
            glob("*.txt *.pl");
            \end{perlcode}
        \item \textbf{File test operators}
            \begin{itemize}
                \item -e File exists.
                \item -r File is readable
                \item -w File is writable
                \item -x File is executable
                \item -o File is owned by you
                \item -z File has zero size.
                \item -s File has nonzero size (returns size).
                \item -f File is a plain file (as opposed to a directory,
                \item symbolic link, device etc.)
                \item -d File is a directory.
                \item -l File is a symbolic link.
                \item -p File is a named pipe (FIFO), or Filehandle is a pipe.
                \item -S File is a socket.
                \item -b File is a block special file.
                \item -c File is a character special file.
                \item -t Filehandle is opened to a tty.
                \item -u File has setuid bit set.
                \item -g File has setgid bit set.
                \item -k File has sticky bit set.
                \item -T File is a text file.
                \item -B File is a binary file (opposite of -T).
                \item -M Days since file last modified, when script started.
                \item -A Same for access time.
                \item -C Same for inode change time.
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
                #!/usr/bin/perl -w
                use strict;
                unless (-e "config.txt") {
                    die "Config file doesn’t exist";
                }

                # or equivalently...
                die "Config file doesn’t exist" unless -e "config.txt";
            \end{perlcode}
        \item \textbf{Finding information about files}: We can find out various information about files by using file test operators and functions such as stat().
            \bigbreak \noindent 
            In Perl, the built-in stat() function returns a 13-element list containing detailed status information and metadata for a specific file, directory, or filehandle
            \bigbreak \noindent 
            stat() a filename expression, a filehandle, or a directory handle. If you leave the argument blank, it defaults to evaluating the global variable \$\_.
            \bigbreak \noindent 
            \begin{perlcode}
                # Capturing all 13 elements into distinct scalar variables
                my ($dev, $ino, $mode, $nlink, $uid, $gid, $rdev, $size, 
                    $atime, $mtime, $ctime, $blksize, $blocks) = stat($filename);
            \end{perlcode}
            \bigbreak \noindent 
            When stat() is successful, it returns the following fields in this exact sequence:
            \bigbreak \noindent 
            \begin{center}
                \begin{tabularx}{\textwidth}{@{}lXX@{}}
                    \toprule
                    \textbf{Index}& \textbf{Element}& \textbf{Description}\\
                    \midrule
                    0-6& \$dev - \$rdev &Device, Inode, Mode, Links, UID, GID, Rdev \\[2ex]
                    7 &\$size &Total size of the file in bytes\\[2ex]
                    8-10& \$atime, \$mtime, \$ctime &Access, Modify, Change times (Epoch seconds)\\[2ex]
                    11-12& \$blksize, \$blocks &Block size and count \\
                    \bottomrule
                \end{tabularx}
            \end{center}
            \textbf{Note:} If stat() fails, it returns an empty list () in list context or 0 in scalar context.
        \item \textbf{Multiple file tests}: Perl caches the result of file tests in a special filehandle called \_ (underscore). Performing tests on this filehandle can often avoid subsequent system calls, resulting in a slight performance gain.
            \bigbreak \noindent 
            \begin{perlcode}
                if(-r $file && -w _) {
                    # ...
                }
            \end{perlcode}
        \item \textbf{Changing the working directory}: The function chdir allows you to change your program’s working directory. All relative file access from that point on will use the new directory. Note that this does not change the working directory of the calling process
            \bigbreak \noindent 
            \begin{perlcode}
                # Archive log files
                my $tar = "/bin/tar";
                my $date = "01-01-00";
                my $directory = "/var/log/apache/";

                unless( chdir($directory) ) {
                    die "Failed to chdir to $directory: $!";
                }

                # Get all files in this directory
                my @files = glob("*.log*");
                system("$tar -czf weblogs.$date.tgz @files") if @files;
            \end{perlcode}
        \item \textbf{CWD module}: 
            \bigbreak \noindent 
            To find out what your current working directory is, we can use the Cwd module:
            \bigbreak \noindent 
            \begin{perlcode}
                use Cwd;
                my $current_working_directory = getcwd();
            \end{perlcode}
        \item \textbf{Recursing down directories}: The built-in functions described above do not enable you to easily recurse through subdirectories. Luckily, the File::Find module is part of the standard library distributed with Perl 5.
            \bigbreak \noindent 
            File::Find emulates Unix’s find command. It takes as its arguments a subroutine to execute for each file found, and a list of directories to search. Note that to pass a reference to a subroutine we prefix the name of the subroutine with \string\&
            \bigbreak \noindent 
            \begin{perlcode}
                #!/usr/bin/perl -w
                use strict;
                use File::Find;

                print "Enter the directory to start searching in: ";
                chomp(my $dir = <STDIN>);

                # find takes a subroutine reference and the directory to start working from.
                find (\&wanted, $dir);

                sub wanted {
                    if(/\.pl$/) { # See if it’s a .pl file
                        print "$File::Find::name\n"; # Print the current file name.
                    }
                }
            \end{perlcode}
            \bigbreak \noindent 
            For each file found, certain variables are set.
            \begin{itemize}
                \item \$\_ is set to the name of the current file.
                \item \$File::Find::dir is set to the directory that contains the file.
                \item \$File::Find::name contains the full name of the file, i.e. \$File::Find::dir/\$\_.
            \end{itemize}
            File::Find automatically changes your current working directory to the same as the file you are currently examining. Thus there’s rarely a need to use \$File::Find::dir. If all you want to do is process the file regardless of its location on the file system you can simply open the file using the name in \$\_.
        \item \textbf{opendir and readdir}: We can also open directories for access by using the opendir() function. Once a directory is open, we can read file names from it using the readdir() function.
            \bigbreak \noindent 
            To read the contents of files in the directory, you still need to open each one using the open() function.
            \bigbreak \noindent 
            \begin{perlcode}
                # $ENV{HOME} stores the home directory on Unix platforms, use
                # $ENV{HOMEPATH} for MS Windows

                opendir(HOMEDIR, $home) or die "Can’t read dir $home: $!";

                my @files = readdir(HOMEDIR);

                closedir HOMEDIR;
            \end{perlcode}
        \item \textbf{Scalar directory handles}: Under Perl 5.6.1 and above you can provide a scalar as the argument to readdir. This allows you to have scalar directory handles which have scope and makes it easier for you to pass them to subroutines or include them in hashes and arrays. Just like scalar filehandles, these are the preferred option if you can use them.
            \bigbreak \noindent 
            \begin{perlcode}
                my $homedir;
                opendir($homedir, $home) or die "Can’t read dir $home: $!";
                my @files = readdir($homedir);
            \end{perlcode}
        \item \textbf{glob and readdir}: 
            \begin{center}
                \begin{tabularx}{\textwidth}{@{}XX@{}}
                    \toprule
                    \textbf{glob}& \textbf{readdir} \\

    \unsect{Subroutines}
    \begin{itemize}
        \item \textbf{Creating and calling subroutines}        
            \bigbreak \noindent 
            \begin{perlcode}
                sub fn {
                    ...
                }

                fn(); # Preferred method of calling
                &fn();
                &fn;
                fn;
            \end{perlcode}
            \bigbreak \noindent 
            The older ampersand syntax bypasses any defined prototypes and implicitly passes the caller's current @\_ argument array.
            \bigbreak \noindent 
            You can pass arguments to a subroutine by including them in the parentheses when you call it. The arguments end up in a special array called @\_ which is only visible inside the subroutine.
        \item \textbf{Shift and unshift}: The Perl shift function removes and returns the first element of an array. This shortens the array by one and shifts all subsequent elements to the left. If the target array is empty, it returns undef
            \bigbreak \noindent 
            The unshift function adds one or more elements directly to the beginning of an array. It is the exact opposite of the shift function, which removes an item from the front.
            \bigbreak \noindent 
            \begin{perlcode}
                sub print_headers {
                    my $title = shift || "Untitled";
                    my $author = shift || "Anonymous";
                    print "$title\n
                    print "by\n
                    print "$author\n";
                }
            \end{perlcode}
        \item \textbf{Passing arrays and hashes}: To pass in a single array or hash to a subroutine, make it the final element in your argument list. 
            \bigbreak \noindent 
            Passing in more than one array or hash causes problems. This is because of list flattening. When Perl sees a number of items in parentheses these are combined into one big list.
            \bigbreak \noindent 
            \begin{perlcode}
                # Flatten two lists into one big list and put that in an array
                my @biglist = (@list1, @list2);

                # Flatten (join) two hashes into one big list an put that in a hash
                my %bighash = (%hash1, %hash2);
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                my @colours = qw/red blue white green pink/;
                my @chosen = qw/red white green/;

                print_unchosen(@chosen, @colours);

                sub print_unchosen {
                    my (@chosen, @colours) = @_;

                    # at this point @chosen contains:
                    # (red white green red blue white green pink)
                    # and @colours contains () - the empty list.
                }
            \end{perlcode}
            \bigbreak \noindent 
            We can avoid this problem by using references:
            \bigbreak \noindent 
            \begin{perlcode}
                my @colours = qw/red blue white green pink/;
                my @chosen = qw/red white green/;
                print_unchosen(\@chosen, \@colours);
                sub print_unchosen {
                    my ($chosen, $colours) = @_;
                    my @chosen = @$chosen;
                    my @colours = @$colours;
                    # at this point @chosen contains:
                    # (red white green)
                    # and @colours contains (red blue white green pink)
                }
            \end{perlcode}
        \item \textbf{Default arguments}: Starting in Perl v5.36, subroutine signatures are stable and enabled automatically when you specify use v5.36; or higher. You can define default values directly inside the parameter list using =, //=, or ||=.
            \bigbreak \noindent 
            \begin{perlcode}
                use v5.36;

                # 1. Standard Default (=)
                # Triggered only if the argument is omitted entirely
                sub greet ($name, $greeting = "Hello") {
                    say "$greeting, $name!";
                }
                greet("Alice");           # Hello, Alice!
                greet("Bob", "Good morning"); # Good morning, Bob!
                greet("Charlie", undef);  # Prints: , Charlie! (undef treated as a value)

                # 2. Defined-or Default (//=) - Added in v5.38+
                # Triggered if omitted OR passed as undef
                sub set_timeout ($time //= 30) {
                    say "Timeout is $time seconds.";
                }
                set_timeout();       # Timeout is 30 seconds.
                set_timeout(undef);  # Timeout is 30 seconds.

                # 3. Logical-or Default (||=) - Added in v5.38+
                # Triggered if omitted, undef, or any false value (0, "")
                sub set_status ($status ||= "active") {
                    say "Status: $status";
                }
                set_status(0);       # Status: active (0 is false)
            \end{perlcode}
            \bigbreak \noindent 
            Because Perl does not strictly enforce the count of elements in @\_ natively, all positional arguments are technically optional unless you explicitly check them.
            \bigbreak \noindent 
            \begin{perlcode}
                sub connect_db {
                    # Unpack parameters from @_
                    my ($host, $port, $timeout) = @_;

                    # Assign fallback values if they aren't provided (or are undef)
                    $port    //= 3306;
                    $timeout //= 30;

                    print "Connecting to $host:$port (Timeout: $timeouts)\n";
                }

                connect_db("localhost");            # Uses defaults for port and timeout
                connect_db("127.0.0.1", 8080);      # Override port, uses default timeout
            \end{perlcode}
        \item \textbf{Named arguments}: When your subroutine accepts many optional parameters, remembering the exact positional order becomes difficult. The standard Perl convention is to slurp remaining arguments into a hash, allowing users to pass named parameters
            \bigbreak \noindent 
            \begin{perlcode}
            use v5.10; # For the // operator

            sub create_user {
                my ($username, %options) = @_; # First argument is required, rest are optional pairs

                # Set fallback defaults
                my $role   = $options{role}   // 'subscriber';
                my $status = $options{status} // 'active';

                print "Created $username as a $role ($status)\n";
            }

            # Callers can pass options in any order, or skip them entirely
            create_user("jdoe");
            create_user("msmith", role => "admin");
            create_user("rrock", status => "pending", role => "moderator");
            \end{perlcode}
        \item \textbf{Ampersand fn name}: If you call a subroutine using the ampersand and omit parentheses (e.g., \&my\_sub;), Perl automatically passes the caller's current argument array (@\_
            \bigbreak \noindent 
            Also, if you name a custom subroutine the same name as a built-in Perl function or keyword, the ampersand forces Perl to run your custom subroutine instead of the built-in version.
        \item \textbf{Subroutine references}: When paired with a backslash (\&my\_sub), it does not call the function. Instead, it creates a reference to the subroutine, which allows you to pass the function around as data
            \bigbreak \noindent 
            When you use parentheses, it clears the argument list.
        \item \textbf{Function prototypes}: In Perl, function prototypes are a mechanism used to change how the Perl parser interprets a subroutine's arguments, primarily allowing user-defined functions to mimic built-in Perl functions.
            \bigbreak \noindent 
            Unlike prototypes in languages like C, C++, or Java, Perl prototypes do not act as traditional function signatures. Instead of validating types at runtime, they force context coercion on variables and change how arguments are parsed at compile time
            \bigbreak \noindent 
            Prototypes are declared by adding special characters inside parentheses right after the subroutine name:
            \begin{itemize}
                \item \$ Forces scalar context on the argument.
                \item @ Consumes all remaining arguments as a list (slurpy).
                    \bigbreak \noindent 
                    An @ prototype is slurpy, so it must appear at the end of the prototype:
                \item \% Consumes all remaining arguments as a hash.
                    \bigbreak \noindent 
                    Internally, Perl still passes a flat list:
                    \bigbreak \noindent 
                    The \% prototype causes the remaining arguments to be evaluated in list context. It does not guarantee that the arguments form a valid hash, so an odd number of arguments is still possible.
                    \bigbreak \noindent 
                    It can follow mandatory arguments:
                    \bigbreak \noindent 
                    \begin{perlcode}
                    sub configure ($%) {
                        my ($name, %options) = @_;
                    }

                    configure(
                        "window",
                        width  => 800,
                        height => 600,
                    );
                    \end{perlcode}
                \item \& Requires a code block or anonymous subroutine reference.
                    \bigbreak \noindent 
                    When \& is the first prototype character, the caller can pass a bare block:
                    \bigbreak \noindent 
                    \begin{perlcode}
                        sub repeat (&$) {
                            my ($code, $count) = @_;

                            $code->() for 1 .. $count;
                        }

                        repeat {
                            print "Hello\n";
                        } 3;
                    \end{perlcode}
                    \bigbreak \noindent 
                    This is approximately equivalent to:
                    \bigbreak \noindent 
                    \begin{perlcode}
                        repeat(sub {
                            print "Hello\n";
                        }, 3);
                    \end{perlcode}
                \item * Accepts a typeglob. The * prototype is commonly used for filehandles:
                    \bigbreak \noindent 
                    \begin{perlcode}
                        sub write_message (*$) {
                            my ($handle, $message) = @_;
                            print $handle "$message\n";
                        }

                        write_message(STDOUT, "Hello");
                        write_message(STDERR, "An error occurred");
                    \end{perlcode}
                    \bigbreak \noindent 
                    It can also accept a typeglob explicitly:
                    \bigbreak \noindent 
                    \begin{perlcode}
                    write_message(*STDOUT, "Hello");
                    \end{perlcode}
                    \bigbreak \noindent 
                    The * prototype supports Perl’s bareword filehandle syntax. It does not strictly enforce that the value is a typeglob at runtime.
                \item ; Separates mandatory arguments (before ;) from optional ones (after ;).
                    \bigbreak \noindent 
                    \begin{perlcode}
                        sub greet ($;$) {
                            my ($name, $greeting) = @_;

                            $greeting //= "Hello";

                            print "$greeting, $name!\n";
                        }
                    \end{perlcode}
                \item \textbackslash \_Requires a literal variable starting with that character and passes it by reference. It means that the caller must provide an actual variable of the corresponding kind. Perl then passes a reference to it automatically.
            \end{itemize}
            \bigbreak \noindent 
            \textbf{Note:} The subroutine must be declared before its calls for the prototype to take effect.
            \bigbreak \noindent 
            Also, you cannot write something like 
            \bigbreak \noindent 
            \begin{perlcode}
                sub _display(first, @) { ... }
            \end{perlcode}
            \bigbreak \noindent 
            because a Perl prototype describes the context and syntactic form of each argument. It does not declare or name parameters.
            \bigbreak \noindent 
            The characters inside the parenthesis must be entirely prototype characters. To require one scalar argument followed by any number of additional arguments, write:
            \bigbreak \noindent 
            \begin{perlcode}
                sub _display($@) { ... }
            \end{perlcode}
            \bigbreak \noindent 
            Modern Perl also supports actual named parameter declarations through signatures:
            \bigbreak \noindent 
            \begin{perlcode}
            use v5.36;
            sub _display($first, @remaining) { ... }
            \end{perlcode}
            \bigbreak \noindent 
            Here, (\$first, @remaining) is a signature, not a prototype. It creates the lexical variables \$first and @remaining automatically.
            \bigbreak \noindent 
            Use signatures when your goal is to name and unpack parameters. Use prototypes only when you intentionally want to alter how Perl parses or evaluates calls to the subroutine.
        \item \textbf{Bypassing prototype checking (ampersand prefix)}: If a subroutine has a defined prototype (which restricts or formats the arguments it accepts), prefixing the call with an ampersand will completely ignore the prototype rules.
        \item \textbf{Anonymous functions (anonymous subroutine / subref)}: . Instead of adding a name to the symbol table, it returns a code reference (CODE ref) that can be stored in a variable, passed to other functions, or executed immediately.
            \bigbreak \noindent 
            To create one, simply omit the name after the sub keyword. You typically assign this definition to a scalar variable:
            \bigbreak \noindent 
            \begin{perlcode}
            # Defining an anonymous function and storing its reference
            my $say_hello = sub {
                my ($name) = @_;
                print "Hello, $name!\n";
            }; # Note the trailing semicolon, as this is an assignment statement
            \end{perlcode}
            \bigbreak \noindent 
            Because the variable holds a reference, you must dereference it to execute the code. There are two common ways to do this:
            \bigbreak \noindent 
            \begin{perlcode}
            $say_hello->("Alice");  # Outputs: Hello, Alice!
            &{$say_hello}("Bob");   # Outputs: Hello, Bob!
            \end{perlcode}
            \bigbreak \noindent 
            If you only need to run an anonymous function once right where you define it, you can enclose the definition in parentheses and invoke it immediately
            \bigbreak \noindent 
            \begin{perlcode}
            (sub { print "Running immediately!\n" })->();
            \end{perlcode}
            \bigbreak \noindent 
            Anonymous functions in Perl act as closures. This means they can "capture" and remember lexical variables (my) from the surrounding scope where they were created, even after that scope has exited.
            \bigbreak \noindent 
            \begin{perlcode}
                sub make_multiplier {
                    my ($multiplier) = @_;

                    # Returns an anonymous function that retains access to $multiplier
                    return sub {
                        my ($number) = @_;
                        return $number * $multiplier;
                    };
                }

                my $triple = make_multiplier(3);
                print $triple->(5); # Outputs 15
            \end{perlcode}
        \item \textbf{Subroutine attributes}: In Perl, subroutine attributes allow you to attach compile-time metadata or behavior modifications to your subroutines. They are specified by placing a colon (:) after the subroutine name (or signature/prototype) and listing the attributes.
            \bigbreak \noindent 
            Attributes can be attached to standard named subroutines, forward declarations, or anonymous subroutines:
            \begin{itemize}
                \item \textbf{lvalue:} Allows the subroutine to act as a modifiable value that can be assigned to directly (like a variable). The subroutine must return a modifiable scalar variable.
                    \bigbreak \noindent 
                    \begin{perlcode}
                        sub name :lvalue {
                            return $name;
                        }

                        name() = "Nathan";
                    \end{perlcode}
                    \bigbreak \noindent 
                    Normally, assigning to a subroutine call is illegal. With :lvalue, Perl treats the value returned by the subroutine as the storage location to modify.
                    \bigbreak \noindent 
                    \begin{perlcode}
                        use strict;
                        use warnings;

                        my $value = 10;

                        sub value :lvalue {
                            $value;
                        }

                        value() = 25;

                        print $value;       # 25
                        print value();      # 25
                    \end{perlcode}
                    \bigbreak \noindent 
                    This can be used to create clean object accessors
                    \bigbreak \noindent 
                    \begin{perlcode}
                        package Person;

                        sub new {
                            my ($class, $name) = @_;

                            return bless {
                                name => $name,
                            }, $class;
                        }

                        sub name :lvalue {
                            my ($self) = @_;
                            $self->{name};
                        }
                    \end{perlcode}
                    \bigbreak \noindent 
                    \begin{perlcode}
                        my $person = Person->new("Nathan");

                        print $person->name;          # Nathan
                    \end{perlcode}
                    \bigbreak \noindent 
                    Perl “secretly” passes a package name when you call a subroutine using method-call syntax, most commonly with ->.
                    \bigbreak \noindent 
                    \begin{perlcode}
                    PackageName->method(arguments);
                    \end{perlcode}
                    \bigbreak \noindent 
                    is equivalent to 
                    \bigbreak \noindent 
                    \begin{perlcode}
                    PackageName::method("PackageName", arguments);
                    \end{perlcode}
                \item \textbf{method:} Explicitly marks the subroutine as an object-oriented method. It primarily tells Perl not to throw an "Ambiguous call" warning if the method shares a name with a core function
                \item \textbf{:prototype(...)}: Assigns a prototype to the subroutine
                    \bigbreak \noindent 
                    \begin{perlcode}
                        sub fn : prototype($$) { ... }
                    \end{perlcode}
                    \bigbreak \noindent 
                    It is equivalent to the older prototype placement:
                    \bigbreak \noindent 
                    \begin{perlcode}
                        sub fn($$) { ... }
                    \end{perlcode}
            \end{itemize}
        \item \textbf{:const}: :const turns an anonymous subroutine into a constant subroutine. Perl executes the subroutine immediately when the sub expression is evaluated, captures its return value, and uses that captured value for every future call.
            \bigbreak \noindent 
            \begin{perlcode}
                my $number = 10;

                my $get_number = sub :const {
                    $number
                };

                $number = 20;

                print $get_number->();    # 10
            \end{perlcode}
            \bigbreak \noindent 
            The body does not run when \$get_number->() is called. It ran earlier—when the anonymous subroutine was created.
            \bigbreak \noindent 
            This allows more complicated initialization:
            \bigbreak \noindent 
            \begin{perlcode}
                my $get_value = sub :const {
                    my $x = 5;
                    my $y = 7;
                    $x * $y
                };

                print $get_value->();    # 35
            \end{perlcode}
            \bigbreak \noindent 
            It applies only to anonymous subroutines. It cannot be placed directly on a named subroutine.


    \end{itemize}

        \item \textbf{Overloading}: In Perl, overloading usually means defining how objects behave when used with built-in operators such as +, -, ==, "", or 0+. 
            \bigbreak \noindent 
            \begin{perlcode}
                use overload
                '+'  => \&add,
                '""' => \&to_string,
                fallback => 1;

                sub new {
                    my ($class, $x, $y) = @_;

                    return bless {
                        x => $x,
                        y => $y,
                    }, $class;
                }

                sub add {
                    my ($self, $other, $swapped) = @_;

                    return Point->new(
                        $self->{x} + $other->{x},
                        $self->{y} + $other->{y},
                    );
                }

                sub to_string {
                    my ($self) = @_;

                    return "($self->{x}, $self->{y})";
                }
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                my $p1 = Point->new(2, 3);
                my $p2 = Point->new(4, 5);

                my $p3 = $p1 + $p2;

                print "$p3\n";    # (6, 8)

                use overload

            \end{itemize}

                sub subtract {

    \unsect{Regular expressions}
    \begin{itemize}
        \item \textbf{Matching operator}: The most basic regular expression operator is the matching operator, m/PATTERN/.
            \begin{itemize}
                \item Works on \$\_ by default.
                \item In scalar context, returns true (1) if the match succeeds, or false (the empty string) if the match fails.
                \item In list context, returns a list of any parts of the pattern which are enclosed in parentheses. If there are no parentheses, the entire pattern is treated as if it were parenthesised.
                \item The m is optional if you use slashes as the pattern delimiters.
                \item If you use the m you can use any delimiter you like instead of the slashes. This is very handy for matching on strings which contain slashes, for instance directory names or URLs.
                \item Using the /i modifier on the end makes it case insensitive.
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
                while (<>) {
                    print if m/foo/;
                }
            \end{perlcode}
        \item \textbf{s/pattern/replacement}: This is the substitution operator, and can be used to find text which matches a pattern and replace it with something else.
            \begin{itemize}
                \item Works on \$\_ by default.
                \item In scalar context, returns the number of matches found and replaced.
                \item In list context, behaves the same as in scalar context and returns the number of matches found and replaced (a cause of more than one mistake...).
                \item You can use any delimiter you want, the same as the m// operator.
                \item Using /g on the end of it matches globally, otherwise matches (and replaces) only the first instance of the pattern.
                \item Using the /i modifier makes it case insensitive.
            \end{itemize}
        \item \textbf{Binding operators}: If we want to use m// or s/// to operate on something other than \$\_ we need to use binding operators to bind the match to another string.
            \begin{itemize}
                \item =$\sim$ True if the pattern matches
                \item !$\sim$ True if the pattern doesn’t match
            \end{itemize}
            The most common use is to test if a string matches a regular expression. It returns a true value if it matches, and false if it doesn't.
            \bigbreak \noindent 
            \begin{perlcode}
                my $text = "The quick brown fox jumps over the lazy dog";

                # Evaluates to true because "fox" is in the string
                if ($text =~ /fox/) {
                    print "Found a fox!\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            You can use $=\sim$ with the s/// operator to find a pattern and replace it. This modifies the original variable on the left
            \bigbreak \noindent 
            \begin{perlcode}
                my $greeting = "Hello World";

                # Replaces "World" with "Perl"
                $greeting =~ s/World/Perl/; 

                print $greeting; # Outputs: Hello Perl
            \end{perlcode}
            \bigbreak \noindent 
            When you use matching parentheses () in your regular expression, $=\sim$ can be used to extract those specific pieces into variables.
            \bigbreak \noindent 
            \begin{perlcode}
                my $date = "2026-08-20";

                # Captures the digits into $1, $2, and $3
                if ($date =~ /(\d{4})-(\d{2})-(\d{2})/) {
                    print "Year: $1, Month: $2, Day: $3\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            does not match a pattern, use the $!\sim$ operator instead.
            \bigbreak \noindent 
            \begin{perlcode}
                my $email = "user-at-domain.com";

                if ($email !~ /@/) {
                    print "Invalid email: Missing '@' symbol.\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            In Perl, \$1, \$2, \$3 (and so on) are special variables that hold captured text from the most recent successful regular expression match.
        \item \textbf{Modifiers}: 
            \begin{itemize}
                \item /i Make match/substitute match case insensitive
                \item /g Make substitute global (all occurrences are changed)
                \item /m – Multi-line mode. Causes $\land$ and \$ to match the start and end of any line within the string rather than just the absolute string boundaries.
                \item /s – Single-line mode. Treats the string as a single line, allowing the dot (.) metacharacter to match newline (\textbackslash n) characters.
                \item /x – Extended legibility. Tells Perl to ignore unescaped whitespace and allow comments (\#) inside the regex pattern for clearer layout formatting
                \item /e – Evaluate replacement. Treats the replacement side as a block of Perl code to execute, utilizing its return value as the final replacement text
                \item /ee – Double evaluate. Evaluates the string on the replacement side as a Perl string, and then runs eval a second time on the result.
                \item /r – Non-destructive substitution. Instead of modifying the original variable, it performs the operation and returns the mutated string copy.
                \item /a – ASCII-only restrictions. Forces character classes like \textbackslash d, \textbackslash s, and \textbackslash w to strictly match ASCII characters only.
                \item /u – Unicode rules. Forces character classes to abide by full Unicode rules (the default setting for most modern Perl scripts).
                \item /l – Locale rules. Instructs Perl to use the underlying system's runtime locale setting.
                \item /d – Default rules. Uses old, backwards-compatible platform defaults.

            \end{itemize}
            You can also activate or deactivate modifiers dynamically inside a regex pattern using the (?imsx-imsx) synt
            \begin{itemize}
                \item (?i)apple matches "Apple" or "APPLE" inline.
                \item (?-i)apple turns off case-insensitivity from that point forward.
            \end{itemize}
        \item \textbf{Meta characters}: 
            \begin{itemize}
                \item $\land$ Start of string
                \item \$ End of string
                \item . Any single character except \textbackslash n
                \item \textbackslash n Newline
                \item \textbackslash t Matches a tab
                \item \textbackslash s Any whitespace character, such as space, tab, or newline
                \item \textbackslash S Any non-whitespace character
                \item \textbackslash d Any digit (0 to 9)
                \item \textbackslash D Any non-digit
                \item \textbackslash w Any "word" character - alphanumeric plus underscore (\_)
                \item \textbackslash W Any non-word character
                \item \textbackslash b A word break - the zero-length point between a word character (as defined above) and a non-word character.
                \item \textbackslash B A non-word break - anything other than a word break
            \end{itemize}
        \item \textbf{Quantifiers}
            \begin{itemize}
                \item ? 0 or 1
                \item * 0 or more
                \item + 1 or more
                \item \{n\} match exactly n times
                \item \{n,\} match n or more times
                \item \{n,m\} match between n and m times
            \end{itemize}
        \item \textbf{Character classes}: Created the usual way with brackets
            \begin{itemize}
                \item $\land$ negates the class
                \item - specifies a range of characters. To mach a literal -, it must be either the first or the last character in the class.
                \item \$, ., (), \{\}, *, + and other meta characters taken literally
            \end{itemize}
        \item \textbf{Match variable (\$\&)}: This special variable holds whatever the last regex matched.
        \item \textbf{Alternation}: Alternation is done the usual way
            \bigbreak \noindent 
            \begin{perlcode}
            /^(rabbit|chicken|dog)$/
            \end{perlcode}
        \item \textbf{Atoms}: In regular expressions, an atom is the most basic, single unit of a pattern match. It either matches a specific set of characters or positions, and quantifiers (like * or +
            \bigbreak \noindent 
            We use it to mean "something that is a chunk of regular expression in its own right". Atoms can be arbitrarily created by simply wrapping things in round brackets.
            \begin{itemize}
                \item \textbf{Literal characters:} A single ordinary letter or number (like a or 7).
                \item \textbf{Character classes:} Brackets matching any single character inside them (like [abc] or [$\land$0-9]).
                \item \textbf{The wildcard dot:} The . symbol matching any character.
                \item \textbf{Escaped characters:} Special shorthands (like \textbackslash d, \textbackslash w, or \textbackslash s).
                \item \textbf{Grouped expressions:} Parentheses surrounding a sub-pattern (like (abc)) treated as one combined unit.
            \end{itemize}
        \item \textbf{Capturing matched strings to scalars}: Perl provides an easy way to extract matched sections of a regular expression for later use. Any part of a regular expression that is enclosed in parentheses is captured and stored into special variables. The substring that matches first set of parentheses will be stored in \$1, and the substring that matches the second set of parentheses will be stored in \$2 and so on. There is no limit on the number of parentheses and associated numbered variables that you can use.
            \bigbreak \noindent 
            \begin{perlcode}
                /(\w)(\w)/; # matches 2 word characters and stores them in $1, $2
                /(\w+)/; # matches one or more word characters and stores them in $1
            \end{perlcode}
            \bigbreak \noindent 
            Parentheses are numbered from left to right by the opening parenthesis.
        \item \textbf{List context}: Evaluating a regular expression in list context is another way to capture information, with parenthesised sub-expressions being returned as a list. We can use this instead of numbered variables if we like:
            \bigbreak \noindent 
            \begin{perlcode}
                $_ = "Our server is training.perltraining.com.au.";
                my ($full, $host, $domain) = /(([\w-]+)\.([\w.-]+))/;

                print "$1\n"; # prints "training.perltraining.com.au."
                print "$full\n"; # prints "training.perltraining.com.au."
                print "$2 : $3\n"; # prints "training : perltraining.com.au."
                print "$host : $domain\n" # prints "training : perltraining.com.au."
            \end{perlcode}
            \bigbreak \noindent 
            \textbf{Note:} A regular expression that fails to match the given string does not always reset \$1, \$2 etc.
        \item \textbf{Extended regular expressions}: Regular expressions can difficult to follow at times, especially if they’re long or complex. Luckily, Perl gives us a way to split a regular expression across multiple lines, and to embed comments into our regular expression. These are known as extended regular expressions.
            \begin{itemize}
                \item Spaces (including tabs and newlines) in the regular expression are ignored.
                \item Anything after an un-escaped hash (\#) is ignored, up until the end of line.
            \end{itemize}
            Extended regular expressions do not alter the format of the second part in a substitution. This must still be written exactly as you wish it to appear.
            \bigbreak \noindent 
            If you need to include a literal space or hash in an extended expression you can do so by preceding it with a backslash.
            \bigbreak \noindent 
            By using extended regular expressions, we can change this:
            \bigbreak \noindent 
            \begin{perlcode}
                # Parse a line from ’ls -l’
                m{^([\w-]+)\s+(\d+)\s+(\w+)\s+(\w+)\s+(\d+)\s+(\w+\s+\d+\s+[\d:]+)\s+(.*)$};
            \end{perlcode}
            \bigbreak \noindent 
            into
            \bigbreak \noindent 
            \begin{perlcode}
                m{
                    ^                               # Start of line.
                    ([\w-]+)\s+                     # $1 - File permissions.
                    (\d+)\s+                        # $2 - Hard links.
                    (\w+)\s+                        # $3 - User
                    (\w+)\s+                        # $4 - Group
                    (\d+)\s+                        # $5 - File size
                    (\w+\s+\d+\s+[\d:]+)\s+         # $6 - Date and time.
                    (.*)                            # $7 - Filename.
                    $                               # End of line.
                }x;
            \end{perlcode}
        \item \textbf{Greediness}: Regular expressions are, by default, "greedy". This means that any regular expression, for instance .*, will try to match the biggest thing it possibly can. Greediness is sometimes referred to as "maximal matching"
            \bigbreak \noindent 
            \begin{perlcode}
                $_ = "The cat sat on the mat";

                /(c.*t)(.*)(m.*t)/;

                print $1; # prints "cat sat on t"
                print $2; # prints "he "
                print $3; # prints "mat";
            \end{perlcode}
            \bigbreak \noindent 
            It is possible in this example for another set of matches to occur. The first expression c.*t could have matched cat leaving sat on the to be matched by the second expression .*. However, to do that, we need to stop c.*t from being so greedy.
            \bigbreak \noindent 
            To make a regular expression quantifier not greedy, follow it with a question mark. For example .*?. This is sometimes referred to as "minimal matching".
            \bigbreak \noindent 
            \begin{perlcode}
                $_ = "The fox is in the box.";
                /(f.*x)/; # greedy -- $1 = "fox is in the box"
                /(f.*?x)/; # not greedy -- $1 = "fox"
            \end{perlcode}
        \item \textbf{More meta characters}: 
            \begin{itemize}
                \item \textbackslash cX Control character, i.e. CTRL-X
                \item \textbackslash 0nn Octal character represented by nn
                \item \textbackslash xnn Hexadecimal character represented by nn
                \item \textbackslash l Lowercase next character
                \item \textbackslash u Uppercase next character
                \item \textbackslash L Lowercase until \textbackslash E
                \item \textbackslash U Uppercase until \textbackslash E
                \item \textbackslash Q Quote (disable) meta characters until \textbackslash E
                \item \textbackslash E End of lowercase/uppercase/quote
                \item \textbackslash A Beginning of string, regardless of whether /m is used.
                \item \textbackslash Z End of string (or before newline at end), regardless of whether /m is used.
                \item \textbackslash z Absolute end of string, regardless of whether /m is used.
            \end{itemize}
        \item \textbf{Regexp modifiers for multi-line data}: Perl has two modifiers for multi-line data. /s and /m. These can be used to treat the string you’re matching against as either a single line or as multiple lines. Their presence changes the behaviour of caret (\string^), dollar (\$) and dot (.).
            \bigbreak \noindent 
            By default caret matches the start of the string. Dollar matches the end of the string (regardless of newlines). Dot matches anything but a newline character.
            \bigbreak \noindent 
            \begin{itemize}
                \item Using /s forces Perl to treat the target string as a single continuous line, allowing the . character to match newlines as well.
                \item Using /m tells Perl that the string contains multiple lines. It changes \string^ and \$ to match at the beginning and end of any line within the string (directly after or before an embedded newline).
            \end{itemize}
            With the /s modifier, caret and dollar behave the same as in the default case, but dot will match the newline character.
            \bigbreak \noindent 
            With the /m modifier, caret matches the start of any line within the string, dollar matches the end of any line within the string. Dot does not match the newline character.
            \bigbreak \noindent 
            \begin{center}
                \begin{tabularx}{\textwidth}{@{}XXXXl@{}}
                    \toprule
                    \textbf{Mode}& \textbf{Specified with}& \textbf{\string^ matches...}& \textbf{\$ matches...}& \textbf{Dot matches newline} \\
                    \midrule
                    default &neither /s nor /m &start of string &end of string &No\\[2ex]
                    single-line &/s &start of string &end of string &Yes\\[2ex]
                    multi-line &/m &start of line &end of line &No\\[2ex]
                    clean multi-line &both /m and /s& start of line &end of line &Yes \\
                    \bottomrule
                \end{tabularx}
            \end{center}
        \item \textbf{Back references}: There are several special variables related to regular expressions. The parenthesised names beside them are their long names if you use the English module.
            \begin{itemize}
                \item \$\& is the matched text (MATCH)
                \item \$‘ (dollar backtick) is the unmatched text to the left of the matched text (PREMATCH)
                \item \$’ (dollar forwardtick) is the unmatched text to the right of the matched text (POSTMATCH)
                \item \$1, \$2, \$3, etc. The text matched by the 1st, 2nd, 3rd, etc sets of parentheses.
            \end{itemize}
            All these variables are modified when a match occurs, and can be used in the same way that other scalar variables can be used.
            \bigbreak \noindent 
            When Perl sees you using PREMATCH, MATCH, or POSTMATCH, it assumes that you may want to use them again. This means that it has to prepare these variables after every successful pattern match. This can slow a program down because these variables are "prepared" by copying the string you matched against to an internal location.
        \item \textbf{Non-capturing parenthesis}: If you want to use parentheses simply for grouping, and don’t want them to set a \$1 style variable, you can use a special kind of non-capturing parentheses, which look like (?: ... )

    \end{itemize}

    \subsection{Advanced Regex}
    \begin{itemize}
        \item \textbf{Subroutine call to a numbered capture group (expression recursion)}: 
            \bigbreak \noindent 
            \begin{perlcode}
                (?i)
            \end{perlcode}
            \bigbreak \noindent 
            Re-executes the definition of group $i$ to match a new piece of text
            \begin{itemize}
                \item \textbf{(?1) or (?g1):} Calls the first capture group by its absolute index.
                \item \textbf{(?+1) or (?-1):} Calls a group relative to the current position (e.g., (?-1) calls the previous group).
                \item \textbf{(?\&name):} Calls a named capture group defined by (?<name>...).
                \item \textbf{(?R) or (?0):} Calls the entire regular expression from the very beginning (global recursion).
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
                # Matches: Day-Month-Year where each is a 2-digit number
                # Instead of writing \d{2} three times, we reuse group 1
                /\b(\d{2})-(?1)-(?1)\b/
            \end{perlcode}
        \item \textbf{The \string\\;G anchor}: Every string in Perl has an internal position pointer called pos(). When you do a m//g match, Perl updates this pointer to the end of the match. The next m//g starts searching from that position.
            \bigbreak \noindent 
            \string\\;G anchors a match to exactly that position. Not "somewhere after it." Exactly at pos(). 
            \bigbreak \noindent 
            \begin{perlcode}
                my $str = "aaa bbb ccc";

                # first m//g match finds "aaa" at position 0
                $str =~ m~\G(\w+)~g;
                say $1;          # aaa
                say pos($str);   # 3

                # without \G, the next match could skip ahead
                # WITH \G, it must match right at position 3
                $str =~ m~\G(\w+)~g;    # fails! position 3 is a space, not \w
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                my $str = "aaa bbb ccc";

                $str =~ m~\G(\w+)~g;
                say $1;          
                say pos($str);  

                $str =~ m~\G\s(\w+)~g;    
                say $1;                 # bbb
                say pos($str);          # 7
            \end{perlcode}
        \item \textbf{The GC flag}: There is a subtlety with m//g that trips people up. Normally, when a m//g match fails, Perl resets pos() to 0. Your position is lost. The next match starts over from the beginning.
            \bigbreak \noindent 
            The c flag changes this. With m//gc, a failed match leaves pos() where it was. The position survives failure.
        \item \textbf{The $e$ modifier}:  The replacement side of s/// is normally a string. Put /e on the end, and it becomes Perl code.
            \bigbreak \noindent 
            \begin{perlcode}
                my $text = "I have 3 cats and 12 dogs";

                $text =~ s~(\d+)~$1 * 2~ge;

                say $text;
                # I have 6 cats and 24 dogs
            \end{perlcode}
            \bigbreak \noindent 
            The /e modifier tells Perl: "Do not treat the replacement as a double-quoted string. Treat it as code. Evaluate it. Use the result." Since the replacement is code, you can call any function:
        \item \textbf{Embedded code execution inside regex}: That (?\{ \}) construct is not a lookahead. It is not a comment. It is live Perl code executing inside the regex engine while the match is still in progress. You have access to the match state, you can modify variables, and you can make decisions based on what has been matched so far.
            \bigbreak \noindent 
            \begin{perlcode}
                use feature 'say';

                "Hello World" =~ m~Hello (?{ say "matched Hello, continuing..." })\w+~;
                # Output: matched Hello, continuing...
            \end{perlcode}
            \bigbreak \noindent 
            The code block fires after Hello has matched and before \string\\;w+ starts matching. It is a checkpoint. The engine got this far, so your code runs.
        \item \textbf{Double e}: 
            \bigbreak \noindent 
            \begin{perlcode}
            $text =~ s~(\d+)~'$1 * 1.13'~ee;
            \end{perlcode}
            \bigbreak \noindent 
            First eval produces the string "100 * 1.13". Second eval executes that string as Perl code. Result: 113.

        \item \textbf{Dynamic regex}: You have a list of words. You want to match any of them in a string.
            \bigbreak \noindent 
            \begin{perlcode}
                my @words = qw(foo bar baz quux);
                my $pattern = join '|', map { quotemeta } @words;
                $text =~ m~$pattern~;
            \end{perlcode}
        \item \textbf{Regex recursion}: Handle nested parentheses. Suppose you need to match (something (with nested (parens))).
            \bigbreak \noindent 
            \begin{perlcode}
            my $nested = qr~\(   ( (?: [^()]+ | \( (?1) \) )* )   \)~x;
            \end{perlcode}
        \item \textbf{Loops with regex}: 
            \bigbreak \noindent 
            \begin{perlcode}
                my $db = {
                    name =>; 'Mike',
                    age  =>; '45'
                };

                qq|@{[ reverse sort keys %{$db} ]}|
                    =~ s~\S+~print qq|$&: $db->{$&}\n|~ger;
            \end{perlcode}

    \end{itemize}

    \unsect{References and complex data structures}
    \begin{itemize}
        \item \textbf{Intro}: There are three main uses for Perl references        
            \begin{enumerate}
                \item \textbf{Creating complex data structures:} Perl references can be used to create complex data structures, for instance hashes of arrays, arrays of hashes, hashes of hashes, and more
                \item \textbf{Passing arrays and hashes to subroutines and functions:} Since all arguments to subroutines are flattened to a list of scalars, it is not possible to use two arrays as arguments and have them retain their individual identities without using references.
                \item \textbf{Object-oriented Perl:} References are used extensively in object oriented Perl. In fact, Perl objects are references to data structures.
            \end{enumerate}
        \item \textbf{Creating and dereferencing references}: To create a reference to a scalar, array or hash, we prefix its name with a backslash:
            \bigbreak \noindent 
            \begin{perlcode}
                my $scalar = "This is a scalar";
                my @array = qw(a b c);
                my %hash = (
                    ’sky’ => ’blue’,
                    ’apple’ => ’red’,
                    ’grass’ => ’green’,
                );

                my $scalar_ref = \$scalar;
                my $array_ref = \@array;
                my $hash_ref = \%hash;
            \end{perlcode}
            \bigbreak \noindent 
            Note that all references are scalars, because they contain a single item of information: the memory address of the actual data
        \item \textbf{ref()}: You can find out whether a scalar is a reference or not by using the ref() function, which returns a string indicating the type of reference, or undef if the scalar is not a reference.
        \item \textbf{Dereferencing}: Dereferencing (getting at the actual data that a reference points to) is achieved by prepending the appropriate sigil to the name of the reference. For instance, if we have a hash reference \$hash\_reference we can dereference it by adding a percentage sign: \%\$hash\_reference.
        \item \textbf{Arrow notation}: Uses the C arrow concept for a dereferenced access.
            \bigbreak \noindent 
            \begin{perlcode}
                print $$array_ref[0];
                print $array_ref->[0];
                print $hash_ref->{"sky"};
            \end{perlcode}
        \item \textbf{Anonymous data structures}: We can use anonymous data structures to create complex data structures without having to declare many temporary variables. Anonymous arrays are created by using square brackets instead of round ones. Anonymous hashes use curly braces instead of round ones
            \bigbreak \noindent 
            \begin{perlcode}
            my $array_ref = [’a’, ’b’, ’c’, ’d’];
            my $array_ref = [qw(a b c d)];

            my %transport = (
                ’cars’ => [qw(toyota ford holden porsche)],
                ’planes’ => [qw(boeing harrier)],
                ’boats’ => [qw(clipper skiff dinghy)],
            );

            my $hash_ref = {
                a => 1,
                b => 2,
                c => 3
            };
            \end{perlcode}
            \bigbreak \noindent 
            Data is pulled out of an anonymous data structure using the arrow notation:
        \item \textbf{Complex data structures}: References are most often used to create complex data structures. Since references are scalars, they can be used as values in both hashes and arrays. This makes it possible to create both deep and complex multi-dimensional data structures.
            \bigbreak \noindent 
            The use of references in data structures allows you to create arrays of arrays, arrays of hashes, hashes of arrays and hashes of hashes
        \item \textbf{Disambiguation and curly braces}: Consider 
            \bigbreak \noindent 
            \begin{perlcode}
                my @res = @$array[0];
            \end{perlcode}
            \bigbreak \noindent 
            Does this mean: 
            \begin{itemize}
                \item Find @array.
                \item Look up index 0: \$array[0]
                \item Turn that (\$array[0]) into an array: @\$array[0]
            \end{itemize}
            Or:
            \begin{itemize}
                \item Find the array reference \$array
                \item Treat that as an array: @\$array
                \item Take an array slice with index 0: @\$array[0]
            \end{itemize}
            Perl does the latter, however if that is what we wanted then we should have written \$\$array[0], as that explicitly returns a single (scalar) result.
            \bigbreak \noindent 
            We can force Perl to evaluate our expression as the first interpretation above by using curly braces. This allows us to clearly write:
            \bigbreak \noindent 
            \begin{perlcode}
                my @result = @{$array[0]};
            \end{perlcode}
            \bigbreak \noindent 
            We can use \$\{...\}, @\{...\} or \%\{...\} syntax to evaluate any expression and dereference the result.
        \item \textbf{Data::Dumper}: Often data structures are very complex, and negotiating and printing these structures can be a tiresome exercise. It’s also an unnecessary one, as all the hard work has already been done for you. To save you from having to write specialised printing code in every program for debugging purposes, there’s a special library you may find useful called Data::Dumper.
            \bigbreak \noindent 
            Data::Dumper provides a function which takes Perl data structures and turns them into human readable strings representing the data with in them. It can be used just like this:
            \bigbreak \noindent 
            \begin{perlcode}
            use Data::Dumper;
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                my %HoH = (
                    Jacinta => {
                        age => 26,
                        favourite_colour => "blue",
                        sport => "swimming",
                        language => "Perl",
                    },

                    Paul => {
                        age => 27,
                        favourite_colour => "green",
                        sport => "cycling",
                        language => "Perl",
                    },
                );
                print Dumper \%HoH;
            \end{perlcode}
            \bigbreak \noindent 
            This will print out something similar to:
            \bigbreak \noindent 
            \begin{perlcode}
            $VAR1 = {
                ’Paul’ => {
                    ’language’ => ’Perl’,
                    ’favourite_colour’ => ’green’,
                    ’sport’ => ’cycling’,
                    ’age’ => 27
                },

                ’Jacinta’ => {
                    ’language’ => ’Perl’,
                    ’favourite_colour’ => ’blue’,
                    ’sport’ => ’swimming’,
                    ’age’ => 26
                }
            };
            \end{perlcode}
            \bigbreak \noindent 
            Not only is this easy to read, but it’s also perfectly valid Perl code. This means you can use Data::Dumper to easily give you a structure that you can paste into another program, or which can be ’serialised’ to a file and re-created at a later date. Data::Dumper has a lot more uses beyond simple debugging.
            \bigbreak \noindent 
            Dumper expects to be given one or more references to data structures to dump. If Dumper is provided with a hash or array then every element of the array, or every key and value of the hash, will be considered a separate data structure, and dump separately. The results are not particularly useful:
            \bigbreak \noindent 
            \begin{perlcode}
                # result of: print Dumper %HoH;
                $VAR1 = ’Paul’;
                $VAR2 = {
                    ’language’ => ’Perl’,
                    ’favourite_colour’ => ’green’,
                    ’sport’ => ’cycling’,
                    ’age’ => 27
                };

                $VAR4 = {
                    ’language’ => ’Perl’,
                    ’favourite_colour’ => ’blue’,
                    ’sport’ => ’swimming’,
                    ’age’ => 26
                };
            \end{perlcode}
        \item \textbf{Hard vs soft references}: Hard references point directly to underlying data values in memory, while symbolic references store the string name of a variable and look it up in the symbol table.
            \bigbreak \noindent 
            Hard references are created using the backslash operator or by declaring anonymous data structures
            \bigbreak \noindent 
            \begin{perlcode}
                my $scalar_ref = \$name;          # Reference to a scalar
                my $array_ref  = \@colors;        # Reference to an array
                my $hash_ref   = \%user_data;     # Reference to a hash
                my $sub_ref    = \&my_function;   # Reference to a subroutine
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
            my $array_ref = [ 'apple', 'banana', 'cherry' ];
            my $hash_ref = { name => 'Alice', age => 30 };
            \end{perlcode}
            \bigbreak \noindent 
            the \string\\;( ... ) syntax distributes a backslash to everything inside the parentheses.
            \bigbreak \noindent 
            Soft references are not distinct data types; they are just regular string scalars containing the name of a variable. They are created simply by assigning a string and then dereferencing it.
            \bigbreak \noindent 
            \begin{perlcode}
            no strict 'refs'; # Required to allow symbolic references
            \end{perlcode}
            \bigbreak \noindent 
            You assign a variable's name (as a string) to a scalar, and then dereference that scalar using standard type prefixes
            \bigbreak \noindent 
            \begin{perlcode}
                no strict 'refs'; # Required to allow symbolic references

                our $animal = "Cat"; # Must be a package/global variable, not 'my'
                my $pointer = "animal"; 

                print $$pointer; # Outputs: Cat (Looks up the variable named "animal")
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                no strict 'refs';

                our @fruits = ('apple', 'orange');
                my $list_name = "fruits";

                print $list_name->[0]; # Outputs: apple
            \end{perlcode}

    \unsect{External Files and Packages}
    \begin{itemize}
        \item \textbf{Require}: Perl implements a number of mechanisms for loading code from external files. The most simplest of these is by using the require function: 
            \bigbreak \noindent 
            \begin{perlcode}
            require 'file.pl';
            \end{perlcode}
            \bigbreak \noindent 
            Perl is smart enough to make sure that the same file will not be included twice if it’s required through the same specified name.
            \bigbreak \noindent 
            \begin{perlcode}
                # The file is only included once in the following case:
                require ’file.pl’;
                require ’file.pl’;
            \end{perlcode}
            \bigbreak \noindent 
            Required files must end with a true value. This is usually achieved by having the final statement of the file being:
            \bigbreak \noindent 
            \begin{perlcode}
            1;
            \end{perlcode}
            \bigbreak \noindent 
            Conflicts can occur if our included file declares subroutines with the same name as those that appear in our main program. In most circumstances the subroutine from the included file takes precedence, and a warning is given.
            \bigbreak \noindent 
            The use of require has been largely deprecated by the introduction of modules and the use keyword. If you’re writing a code library from scratch we recommend that you create it as a module. However, require is often found in legacy code and is a useful thing to understand.
            \bigbreak \noindent 
            Any code in the file (except for subroutines) will be executed immediately when the file is required. The require occurs at run-time, this means that Perl will not throw an error due to a missing file until that statement is reached, and any subroutines inside the file will not be accessible until after the require.
            \bigbreak \noindent 
            Variables declared with my are not shared between files, they are only visible inside the block or file where the declaration occurs. To share packages between files we use package variables which are covered later in this chapter.
            \bigbreak \noindent 
            The use of modules (which we will learn about later) allows for external files to be loaded at compile-time, rather than run-time.
        \item \textbf{Use strict and warnings}: 
            Perl pragmas, such as strict and warnings are lexically scoped. Just like variables declared with my, they last until the end of the enclosing block, file or eval.
            \bigbreak \noindent 
            This means that you can turn strict and warnings on in one file without it influencing other parts of your program. Thus, if you’re dealing with legacy code, then your new libraries, modules and classes can be strict and warnings compliant even though the older code is not.
        \item \textbf{Require example}:
            \bigbreak \noindent 
            \begin{perlcode}
                # Greetings.pl
                use strict;
                use warnings;
                my %greeting_in = (
                    en => "Hello",
                    ’en-au’ => "G’day",
                    fr => "Bonjour",
                    jp => "Konnichiwa",
                    zh => "Nihao",
                );

                sub hello {
                    my $language = shift || "en";

                    my $greeting = $greeting_in{$language}
                        or die "Don’t know how to greet in $language";

                    return $greeting;
                }

                1;
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                # program.pl
                use strict;
                require "Greetings.pl";

                print "English: ", hello("en"), "\n"; # Prints "Hello"
                print "Australian: ", hello("en-au"),"\n"; # Prints "G’day"
            \end{perlcode}
        \item \textbf{Packages}: When working with a large project, the chances of naming conflicts increases. Two entirely different files may have two different subroutines with the same name; however it is only the last one loaded that will be used by Perl. Files from different projects may be re-used in new developments, and these may have considerable name clashes. Multiple files can also make it difficult to determine where subroutines are originally declared, which can make debugging difficult.
            \bigbreak \noindent 
            Perl’s packages are designed to overcome these problems. Rather than just putting code into separate files, code can be placed into independent packages, each with its own namespace. By ensuring that package names remain unique, we also ensure that all subroutines and variables can remain unique and easily identifiable.
            \bigbreak \noindent 
            A single file can contain multiple packages, but convention dictates that each file contains a package of the same name. This makes it easy to quickly locate the code in any given package.
            \bigbreak \noindent 
            Writing a package in Perl is easy. We simply use the package keyword to change our current package. Any code executed from that point until the end of the current file or block is done so in the context of the new package.
            \bigbreak \noindent 
            \begin{perlcode}
                package Greetings;
                use strict;
                use warnings;

                my %greeting_in = (
                    en => "Hello",
                    ’en-au’ => "G’day",
                    fr => "Bonjour",
                    jp => "Konnichiwa",
                    zh => "Nihao",
                );

                sub hello {
                    my $language = shift || "en";
                    my $greeting = $greeting_in{$language}
                        or die "Don’t know how to greet in $language";

                    return $greeting;
                }

                1;
            \end{perlcode}
            \bigbreak \noindent 
            The package that you’re in when the Perl interpreter starts (before you specify any package) is called main. Package declarations use the same rules as my, that is, it lasts until the end of the enclosing block, file, or eval.
            \bigbreak \noindent 
            Perl convention states that package names (or each part of a package name, if it contains many parts) starts with a capital letter. Packages starting with lower-case are reserved for pragmas (such as strict).
        \item \textbf{Scoping operator}: Perl provides a scoping operator in the form of a pair of adjacent colons. The scoping operator allows us to refer to information inside other packages, and is usually pronounced "double-colon".
            \bigbreak \noindent 
            \begin{perlcode}
                require "Greetings.pl";

                print Greetings::hello("en"),"\n";
                print Greetings::hello("jp"),"\n";

                # This calls the hello() subroutine in our main package
                # (below), printing "Greetings Earthling".
                print hello(),"\n";

                sub hello {
                    return "Greetings Earthling";
                }
            \end{perlcode}
        \item \textbf{Changing variables in other packages}: Occasionally we may wish to change the value of a variable in another package. It should be very rare that we should need to do this, and it’s not recommended you do so unless this is a documented feature of your package. However, in the case where we do need to do this, we use the scoping operator again.
            \bigbreak \noindent 
            \bigbreak \noindent 
            \begin{perlcode}
                use Carp;

                # Turning on $Carp::Verbose makes carp() and croak() provide
                # stack traces, making them identical to cluck() and confess().
                # This is documented in ’perldoc Carp’.

                $Carp::Verbose = 1;
            \end{perlcode}
            \bigbreak \noindent 
            carp() and croak() are functions from the Carp module that report errors from the calling code's perspective instead of inside your module
            \begin{itemize}
                \item \textbf{carp():} Works like warn(), sending a non-fatal warning, but attributes the line number to the code that called your module.
                \item \textbf{croak():} Works like die(), throwing a fatal error, but attributes the line number to the code that called your module rather than the exact line inside the function.
            \end{itemize}
            cluck() and confess() are error-handling functions provided by the Carp module that include a full stack backtrace to show exactly where and how an error occurred
            \begin{itemize}
                \item cluck() acts like a enhanced warn(). It prints the error message and the full stack trace, but allows the program to keep running.
                \item confess() acts like an enhanced die(). It prints the error message and the full stack trace, then terminates the program immediately.
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
            use Carp qw(cluck confess); # Explicitly importing cluck
            \end{perlcode}
        \item \textbf{Main package}: There’s a shorthand for accessing variables and subroutines in the main package, which is to use double-colon without a package name. This means that \$::foo is the same as \$main::foo
        \item \textbf{Package variables and our}: It is not possible to access lexically scoped variables (those created with my) outside of their enclosing block. This means that we need another way to create variables to make them globally accessible. These global variables are called package variables, and as their name suggests they live inside their current package. The preferred way to create package variables, under Perl 5.6.0 and above, is to declare them with the our statement. Of course, there are alternatives you can use with older version of Perl, which we also show here:
            \bigbreak \noindent 
            \begin{perlcode}
            package Carp;
            our $VERSION = ’1.01’; # Preferred for Perl 5.6.0 and above

            # use vars qw/$VERSION/; # Preferred for older versions
            # $VERSION = ’1.01’;

            # $Carp::VERSION = ’1.01’; # Acceptable but requires that we then
            # always use this full name under strict
            \end{perlcode}
            In all of the cases above, both our package and external code can access the variable using \$Carp::VERSION.

    \end{itemize}

    \pagebreak 
    \unsect{Modules}
    \begin{itemize}
        \item \textbf{Module}: A module is a separate file containing Perl source code, which is loaded and executed at compile time. This means that when you write:
            \bigbreak \noindent 
            \begin{perlcode}
            use CGI;
            \end{perlcode}
            \bigbreak \noindent 
            Perl looks for a file called CGI.pm (.pm for Perl Module), and upon finding it, loads it in and executes the code inside it, before looking at the rest of your program.
            \bigbreak \noindent 
            Sometimes you might choose to pass extra information to the module when you load it. Often this is to request the module create new subroutines in your namespace.
            \bigbreak \noindent 
            \begin{perlcode}
                use CGI qw(:standard);
                use File::Copy qw(copy);
            \end{perlcode}
            \bigbreak \noindent 
            Note the use of qw(), this is a list of words (in our case, just a single word). It’s possible to pass many options to a module when you load it. In the case above, we’re asking the CGI module for the :standard bundle of functions, and the File::Copy module for just the copy subroutine.
            \bigbreak \noindent 
            Each module has a different set of options (if any) that it will accept. You need to check the documentation of the module you’re dealing with to which (if any) are applicable to your needs.
        \item \textbf{Require vs use}: The fundamental difference is that use happens at compile time, while require happens at runtime
            \bigbreak \noindent 
            The use statement is actually a built-in shortcut. Writing use MyModule; is exactly equivalent to executing
            \bigbreak \noindent 
            \begin{perlcode}
                BEGIN {
                    require MyModule;
                    MyModule->import();
                }
            \end{perlcode}
            \begin{center}
                \begin{tabularx}{\textwidth}{@{}lXX@{}}
                    \toprule
                    \textbf{Feature}& \textbf{use}& \textbf{require} \\
                    \midrule
                    Execution Time & Compile time (processed before the rest of the script runs) &Runtime (processed only when the execution line is hit)\\[2ex]
                    Implicit Import & Yes. Automatically calls the module's import method. &No. Does not call import automatically.\\[2ex]
                    File Types & Only loads Perl Modules (.pm files). & Loads both libraries (.pl) and modules (.pm). \\[2ex]
                    Syntax & Expects a bareword name without an extension (e.g., use File::Copy;). &Accepts a bareword or a string expression with a file extension.\\[2ex]
                    Conditionals & Cannot be placed inside if blocks (it will still load at compile time). &Can be placed inside if statements for conditional loading. \\
                    \bottomrule
                \end{tabularx}
            \end{center}
        \item \textbf{No import method}: If you do not write an import method and do not inherit one (like from Exporter), your module will still load perfectly fine, but it will not export anything automatically into the caller's namespace.
            \bigbreak \noindent 
            Perl does not require an import method. If you use use MyModule; and MyModule has no import subroutine, Perl simply skips the step without throwing an error or warning.
            \bigbreak \noindent 
            Because no functions or variables are copied into the main script's namespace, you cannot call them by their short names. You must use their fully qualified package paths.
            \bigbreak \noindent 
            \begin{perlcode}
                # --- MyModule.pm ---
                package MyModule;
                sub say_hello {
                    print "Hello from the module!\n";
                }
                1;

                # --- main.pl ---
                use MyModule;

                # say_hello();       # This will crash! Perl doesn't know what say_hello is.
                MyModule::say_hello(); #  This works perfectly.
            \end{perlcode}
        \item \textbf{Import method}: Because writing a manual import method to manipulate symbol tables is complex, almost all Perl developers inherit the behavior from the core Exporter module.
            \bigbreak \noindent 
            \begin{perlcode}
                package MyMath;
                use strict;
                use warnings;

                # Import the standard 'import' method from the Exporter module
                use Exporter qw(import);

                # Functions in @EXPORT are automatically imported by default
                our @EXPORT = qw(add);

                # Functions in @EXPORT_OK are only imported if explicitly requested
                our @EXPORT_OK = qw(multiply);

                sub add {
                    my ($a, $b) = @_;
                    return $a + $b;
                }

                sub multiply {
                    my ($a, $b) = @_;
                    return $a * $b;
                }

                1; # Modules must return a true value
            \end{perlcode}
        \item \textbf{\%EXPORT\_TAGS}: Group related exportable symbols into convenient shortcut tags. This allows developers importing your module to request an entire category of functions or variables at once by using a colon prefix (:tag\_name)
            \bigbreak \noindent 
            Every symbol listed inside %EXPORT\_TAGS must also be explicitly declared in either @EXPORT or @EXPORT\_OK
            \bigbreak \noindent 
            You cannot nest tag names inside @EXPORT or @EXPORT\_OK
            \bigbreak \noindent 
            Define the groups using an array reference for each tag name.
            \bigbreak \noindent 
            \begin{perlcode}
            our %EXPORT_TAGS = (
                utils => [ qw( validate_email ) ],
                user  => [ qw( create_user delete_user ) ],
                log   => [ qw( log_info log_error ) ],
                all   => [ @EXPORT, @EXPORT_OK ], # Quick shortcut combining everything
            );
            \end{perlcode}
            \bigbreak \noindent 
            When loading the module, prepend a colon (:) to the tag name to pull in that entire group
            \bigbreak \noindent 
            \begin{perlcode}
                # Import only the user management group (:user)
                use MyModule qw(:user); 

                create_user(); # Works!
                delete_user(); # Works!

                # log_info();  # Fails! (Not imported)
            \end{perlcode}
        \item \textbf{Advanced import techniques}: You can combine tags, default exports, and exclusions using specific prefixes
            \begin{itemize}
                \item \textbf{:DEFAULT:} Refers implicitly to everything inside your module's @EXPORT array.
                \item \textbf{!:} Negates/excludes a specific symbol from being imported.
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
                # Imports default functions, the logging tag, but EXCLUDES log_error
                use MyModule qw(:DEFAULT :log !log_error); 
            \end{perlcode}
        \item \textbf{Where does Perl look for modules?}: Perl searches through a list of directories that are determined when the Perl interpretor is compiled. You can see this list (and all the other options Perl was compiled with), by using perl -V
            \bigbreak \noindent 
            The list of directories which Perl searches for modules is stored in the special variable @INC. It’s possible to change @INC so that Perl will search in other directories as well. This is important if you have installed your own private copy of some modules.
            \bigbreak \noindent 
            Of course, being Perl, there’s more than one way to change @INC. Here are some of the ways to add to the list of directories inside @INC:
            \begin{itemize}
                \item Call Perl with the -I command-line switch with the location of the extra directory to search. For example:
                \bigbreak \noindent 
                \begin{perlcode}
                    perl -I/path/to/libs
                \end{perlcode}
                \bigbreak \noindent 
                This can be done either in the shebang line, or on the command-line.
                \item Use the lib pragma in your script to inform Perl of extra directories. For example:
                    \bigbreak \noindent 
                    \begin{perlcode}
                    use lib "/path/to/libs";
                    \end{perlcode}
                \item Setting the PERL5LIB environment variable with a colon-separated list of directories to search. Note that if your script is running with taint checks this environment variable is ignored.
            \end{itemize}
            Since use statements occur before regular Perl code is executed, modifying @INC directly usually does not have the desired effect.
        \item \textbf{Finding installed modules}: Perl comes with many modules in its standard distribution. You can get a list of all of them by doing a perldoc perlmodlib. 
            \bigbreak \noindent 
            Besides from the modules in the standard distribution, you can also see any other modules that were installed on your system by using perldoc perllocal. Generally this file only lists other modules that were installed by hand, or using one of the CPAN installers (more on this later). Modules installed through your operating system’s packaging system may not appear in perldoc perllocal.
            \bigbreak \noindent 
            To find a complete list of modules available on your system, regardless of how they were installed, read the documentation provided by perldoc -q installed.
            \bigbreak \noindent 
            You can get more information on any module that you have installed by using perldoc module\_name. For example, perldoc English will give you information about the English module. You can also use perldoc -l module\_name to locate a particular module, and perldoc -m module\_name to view the source of a module.
        \item \textbf{Using CPAN (Comprehensive Perl Achieve Network) modules}:  CPAN provides more than 9,000 separate and freely available modules. This makes CPAN an excellent starting point when you wish to find modules to help solve your particular problem. However, you should keep in mind that not all CPAN modules are created equal. Some are much better documented and written than others. Some (such as the CGI or DBI) modules have become de-facto standards, whereas others may not be used by anyone except the module’s author.
            \bigbreak \noindent 
            As with any situation when you’re using third party code, you should take the time to determine the suitability of any given module for the task at hand. However, in almost all circumstances it’s better to use or extend a suitable module from CPAN rather than trying to re-invent the wheel.
            \bigbreak \noindent 
            Many of the popular CPAN modules are pre-packaged for popular operating systems. In addition, the CPAN module that comes with Perl can make the task of finding and installing modules from CPAN much easier.
            \bigbreak \noindent 
            Most CPAN modules come with README and/or INSTALL files which tell you how to install the modules. This may vary between operating systems. On Unix and Unix-like operating systems the process is usually:
            \bigbreak \noindent 
            \begin{perlcode}
            perl Makefile.PL
            make
            make test
            make install
            \end{perlcode}
            \bigbreak \noindent 
            For ActiveState Perl installations (which includes most Microsoft Windows machines) the use of PPM (Programmer’s Package Manager) is recommended. PPM provides a command line interface for downloading and installing pre-compiled versions of most CPAN modules.
        \item \textbf{Writing modules}: Modules contain regular Perl code, and for most modules the vast majority of that code is in subroutines. Sometimes there are a few statements which initialise variables and other things before any of those subroutines are called, and those get executed immediately. The subroutines get compiled and tucked away for later use.
            \bigbreak \noindent 
            Besides from the code that’s loaded and executed, two more special things happen. Firstly, if the last statement in the module did not evaluate to true, the Perl compiler throws an exception (usually halting your program before it even starts). This is so that a module could indicate that something went wrong, although in reality this feature is almost never used. Virtually any Perl module you care to look at will end with the statement 1; to indicate successful loading.
            \bigbreak \noindent 
            The other thing that happens when a module is used is that its import subroutine (if one exists) gets called with any directives that were specified on the use line. This is useful if you want to export functions or variables to the program that’s using your module for functional programming but is almost never used (and very often discouraged) for object oriented programming.
            \bigbreak \noindent 
            As you’ve no doubt guessed by now, modules and packages often go hand-in-hand. We know how to use a module, but what are the rules on writing one? The big one is this: A module is a file that contains a package of the same name.
            \bigbreak \noindent 
            That’s it. So if you have a package called Tree::Fruit::Citrus::Lime, the file would be called Tree/Fruit/Citrus/Lime.pm, and you would use it with use Tree::Fruit::Citrus::Lime;.
            \bigbreak \noindent 
            A module can contain multiple packages if you desire. So even though the module is called Chess::Piece, it might also contain packages for Chess::Piece::Knight and Chess::Piece::Bishop. It’s usually preferable for each package to have its own module, otherwise it can be confusing to your users how they can load a particular package.
            \bigbreak \noindent 
            When writing modules, it’s important to make sure that they are well-named, and even more importantly that they won’t clash with any current or future modules, particularly those available via CPAN. If you are writing a module for internal use only, you can start its name with Local:: which is reserved for the purpose of avoiding module name clashes.
            \bigbreak \noindent 
            \textbf{Note:} A module is a file that contains a package of the same name.
        \item \textbf{Use vs require}: Perl offers several different ways to include code from one file into another. use is built on top of require and has the following differences: 
            \begin{itemize}
                \item Files which are used are loaded and executed at compile-time, not run-time. This means that all subroutines, variables, and other structures will exist before your main code executes. It also means that you will immediately know about any files that Perl could not load.
                \item use allows for the import of variables and subroutines from the used package into the current one. This can make programming easier and more concise.
                \item Files called with use can take arguments. These arguments can be used to request special features that may be provided by some modules.
            \end{itemize}
            Both methods:
            \begin{itemize}
                \item Check for redundant loading, and will skip already loaded files.
                \item Raise an exception on failure to find, compile or execute the file.
                \item Translate :: into your systems directory separator.
            \end{itemize}
            Where possible use and Perl modules are preferred over require.
        \item \textbf{extern equivalent}: The equivalent of an extern global variable from C in Perl is an \textbf{our} variable declared in a shared package or module.
            \bigbreak \noindent 
            \begin{perlcode}
                package MyConfig;
                use strict;
                use warnings;

                # Declare a global variable
                our $GlobalSetting = "Active";

                1;
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                use strict;
                use warnings;
                use MyConfig;

                # Access the extern-like global variable using its full package path
                print $MyConfig::GlobalSetting; 

                # Or bring it into your current namespace
                our $GlobalSetting;
                print $GlobalSetting;
            \end{perlcode}
        \item \textbf{Static equivalent}: A my variable is exactly how you restrict scope in Perl, but it behaves like a C static in two distinct ways depending on where you declare it.
            \bigbreak \noindent 
            If you declare a my variable at the top level of a file, it is invisible to other files. This behaves exactly like a file-level static variable in C.
            \bigbreak \noindent 
            \begin{perlcode}
                # Inside MyModule.pm
                use strict;

                my $file_private = 42; # Visible only inside this file

                sub get_value { return $file_private; }
            \end{perlcode}
            \bigbreak \noindent 
            If you want a variable inside a function to keep its value between calls (like a function-level static in C), use Perl's state keyword instead of my. A my variable inside a function is reinitialized every time the function runs.
        \item \textbf{Warnings and strict}: When your module is used by a script, whether or not it runs with warnings depends upon whether the calling script is running with warnings turned on. You can (and should) invoke the use warnings pragma to turn on warnings for your module without changing warnings for the calling script.
            \bigbreak \noindent 
            Your modules should always use strict.
            \bigbreak \noindent 
            \begin{perlcode}
            use strict;
            use warnings;
            \end{perlcode}
        \item \textbf{Exporting and importing subroutines}: 
            Writing your own import function for each and every module would be a tiresome and error-prone process. However, Perl comes with a module called Exporter, which provides a highly flexible interface with optimisations for the common case.
            \bigbreak \noindent 
            Exporter works by checking inside your module for three special data structures, which describe both what you wish to export, and how you wish to export them. These structures are
            \begin{itemize}
                \item @EXPORT symbols to be exported into the user’s name space by default
                \item @EXPORT\_OK symbols which the user can request to be exported
                \item \%EXPORT\_TAGS that allows for bundles of symbols to be exported when the user requests a special export tag.
            \end{itemize}
        \item \textbf{@ISA}: To take advantage of Exporter’s import function we need to let Perl know that our package has a special relationship with the Exporter package. We do this by telling Perl that we inherit from Exporter. Our package and the rest of our program does not need to be written in an object oriented style for this to work.
            \bigbreak \noindent 
            Now when Perl goes looking for the import function it will first look in our package. If it can’t be found there, Perl will look for a special array called @ISA. The contents of the @ISA array is interpreted as a list of parent classes, and each of these will be searched for the missing method.
            \bigbreak \noindent 
            To specify that this package is a sub-class of the Exporter module we include the following lines:
            \bigbreak \noindent 
            \begin{perlcode}
            use Exporter;
            our @ISA = qw(Exporter);
            \end{perlcode}
            \bigbreak \noindent 
            \textbf{Note:} ISA means is-a.
        \item \textbf{use base}: An alternative to adding parent modules to @ISA yourself is to use the base pragma. This allows you to declare a derived class based upon the listed parent classes. Thus the two lines above becomes:
            \bigbreak \noindent 
            \begin{perlcode}
            use base qw(Exporter);
            \end{perlcode}
            \bigbreak \noindent 
            Here’s an example of just using @EXPORT and @EXPORT\_OK. Our hypothetical module, People::Manage is used for managing interpersonal relations.
            \bigbreak \noindent 
            \begin{perlcode}
                package People::Manage;
                use base qw(Exporter);
                use vars qw(@EXPORT @EXPORT_OK);

                @EXPORT = qw(invite $name @friends %addresses); # invite is a subroutine
                @EXPORT_OK = qw(&taunt $spouse @enemies %postcodes); # so is taunt
            \end{perlcode}
            \bigbreak \noindent 
            The base pragma takes care of ensuring that the Exporter module is loaded.
            \bigbreak \noindent 
            The base pragma is available for all versions of Perl above 5.6.0.
        \item \textbf{Polluting the caller's namespace}: Exporting your symbols by default, by populating the @EXPORT array, means that anyone using your module will receive these symbols without having to ask for them. This is generally considered to be bad style, and is sometimes referred to as ’polluting’ the caller’s namespace.
            \bigbreak \noindent 
            Using @EXPORT\_OK allows the user to choose which symbols they wish to bring into their name space. All other symbols can be accessed by using their full name, such as People::Manage::invite(), when required.
        \item \textbf{Importing symbols}: Once your module is written and it exports a few symbols, it’s time to use it. This is done with the use command that we’ve seen with strict and other modules. We can load our module in three ways:
            \begin{enumerate}
                \item use People::Manage; which imports all of the symbols stored in @People::Manage::EXPORT.
                \item use People::Manage (); which imports none of the symbols in either @People::Manage::EXPORT or @People::Manage::EXPORT\_OK.
                \item use People::Manage qw(\$name \$spouse invite); which imports all the listed symbols. If a symbol is mentioned which is not in either @People::Manage::EXPORT or @People::Manage::EXPORT\_OK then a fatal error will occur.
            \end{enumerate}
        \item \textbf{FindBin}:  Import the \$RealBin variable directly into your script's namespace, which holds the absolute, canonical path to the directory containing your script.
            \bigbreak \noindent 
            \begin{perlcode}
            use FindBin qw($RealBin);
            \end{perlcode}
            \bigbreak \noindent 
            Unlike the default \$Bin variable, \$RealBin resolves all symbolic links (symlinks). This means if your script is a shortcut pointing somewhere else, \$RealBin tells you where the physical file actually lives rather than where the shortcut is located.
            \bigbreak \noindent 
            Then, we can do something like
            \bigbreak \noindent 
            \begin{perlcode}
            use lib ($RealBin, "$RealBin/lib");
            \end{perlcode}



    \end{itemize}

    \unsect{Using Perl Objects (Perl OOP)}
    \begin{itemize}
        \item \textbf{OOP in perl}: In Perl, object-oriented programming (OOP) is built on a few deceptively simple rules rather than dedicated language keywords. Classic Perl OOP relies on three core principles: a class is simply a package, an object is a reference that "knows" its class, and a method is a standard subroutine
            \bigbreak \noindent 
            In Perl, there is no class keyword (in older/classic versions). Instead, a package acts as the class. The package defines a separate namespace to prevent variable and subroutine names from colliding with other parts of the program
            \bigbreak \noindent 
            reference to a hash that has been explicitly linked to a specific class. This linking is achieved using the built-in \textbf{bless} function.
            \bigbreak \noindent 
            By convention, the constructor method is named \textbf{new}, though you can technically name it anything
            \bigbreak \noindent 
            \begin{perlcode}
                package Animal;
                use strict;
                use warnings;

                # The Constructor
                sub new {
                    my $class = shift;        # Captures the class name ("Animal")
                    my $self = {              # Creates a reference to an empty hash
                        name => shift,
                        type => shift,
                    };

                    # "Blesses" the hash reference into the class namespace
                    return bless $self, $class; 
                }
                1; # Packages must return a true value
            \end{perlcode}
            \bigbreak \noindent 
            The \textbf{bless} function turns a standard reference into an object by associating it with a specific package (class).
            \bigbreak \noindent 
            Unlike languages with strict object-oriented syntax, an object in Perl is simply a regular data structure (usually a hash reference) that has been explicitly told which class it belongs to. Once a reference is "blessed", you can call the package's subroutines as object methods
            \bigbreak \noindent 
            two-argument form is highly recommended to support class inheritance safely:
            \bigbreak \noindent 
            \begin{perlcode}
            bless REF, CLASSNAME;
            bless REF;
            \end{perlcode}
            \begin{itemize}
                \item \textbf{REF:} Any valid Perl reference (Hash, Array, Scalar, Subroutine, etc.). Hash references are the most common because they allow you to store named attributes.
                \item \textbf{CLASSNAME:} A string containing the name of the package/class. If omitted, Perl blesses the reference into the current package.
                \item \textbf{Return Value:} It returns the newly blessed reference, allowing you to use it instantly or return it at the end of a constructor
            \end{itemize}
            Then, “When this reference is used as an object, look for its methods in this package.”
            \bigbreak \noindent 
            \begin{perlcode}
                package Person;

                sub new {
                    my ($class, $name, $age) = @_;

                    my $self = {
                        name => $name,
                        age  => $age,
                    };

                    bless $self, $class;

                    return $self;
                }
            \end{perlcode}
        \item \textbf{Methods and the arrow syntax}: Methods are just subroutines defined inside the package. When you invoke a method using the arrow operator (->), Perl automatically passes the object itself (or the package name, if it's a class method) as the first hidden argument
            \begin{itemize}
                \item \textbf{Defining a Method:} You must always shift the object (\$self) off the argument array (@\_) first.
                \item \textbf{Getters and Setters:} Because attributes are just keys inside a blessed hash, you write subroutines to read or modify them
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
                sub speak {
                    my $self = shift; # The object itself is passed first
                    print $self->{name} . " says hello!\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                use Animal;

                # Create the object (instantiation)
                my $dog = Animal->new("Fido", "Dog");

                # Call a method
                $dog->speak(); # Outputs: Fido says hello!
            \end{perlcode}
        \item \textbf{Inheritance}: Inheritance is handled by manipulating a special package array called @ISA (which stands for "is a"). Modern classic Perl uses the parent directive to manage this cleanly
            \bigbreak \noindent 
            \begin{perlcode}
                package Dog;
                use parent 'Animal'; # Inherits all methods from Animal
                1;
            \end{perlcode}

        \item \textbf{Tied variables}: In Perl, a tied variable looks like an ordinary scalar, array, hash, or filehandle, but operations on it are handled by methods in a Perl class.
            \bigbreak \noindent 
            This lets you change what assignment, retrieval, deletion, and other normal variable operations actually do.
            \bigbreak \noindent 
            For example, a tied hash could store its values in a database or file instead of ordinary memory:
            \bigbreak \noindent 
            You connect a variable to a class using tie:
            \bigbreak \noindent 
            \begin{perlcode}
                tie VARIABLE, CLASS, ARGUMENTS;
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
            tie %hash, "MyHash", "data.txt";
            \end{perlcode}
            \bigbreak \noindent 
            Perl creates an object from MyHash and forwards operations on \%hash to that object.
            \bigbreak \noindent 
            The methods your class needs depend on the variable type.
            \begin{itemize}
                \item \textbf{Scalar:}
                    \bigbreak \noindent 
                    \begin{perlcode}
                        TIESCALAR
                        FETCH
                        STORE
                    \end{perlcode}
                \item \textbf{Array}: 
                    \bigbreak \noindent 
                    \begin{perlcode}
                        TIEARRAY
                        FETCH
                        STORE
                        FETCHSIZE
                        STORESIZE
                        CLEAR
                        PUSH
                        POP
                        SHIFT
                        UNSHIFT
                        SPLICE
                        EXISTS
                        DELETE
                    \end{perlcode}
                    \bigbreak \noindent 
                    Not every method is always required, but unsupported operations will fail or behave incorrectly.
                \item \textbf{Hash}: 
                    \bigbreak \noindent 
                    \begin{perlcode}
                        TIEHASH
                        FETCH
                        STORE
                        DELETE
                        CLEAR
                        EXISTS
                        FIRSTKEY
                        NEXTKEY
                        SCALAR
                    \end{perlcode}
                    \bigbreak \noindent 
                    FIRSTKEY and NEXTKEY support iteration through operations such as:
                    \bigbreak \noindent 
                    \begin{perlcode}
                        keys %hash;
                        each %hash;
                    \end{perlcode}
                \item \textbf{Filehandle}: 
                    \bigbreak \noindent 
                    \begin{perlcode}
                        TIEHANDLE
                        PRINT
                        PRINTF
                        READ
                        READLINE
                        WRITE
                        CLOSE
                    \end{perlcode}
            \end{itemize}
            \bigbreak \noindent 
            \begin{perlcode}
                package LoggedScalar;

                sub TIESCALAR {
                    my ($class, $initial_value) = @_;

                    return bless {
                        value => $initial_value
                    }, $class;
                }

                sub FETCH {
                    my ($self) = @_;

                    print "Scalar was read\n";
                    return $self->{value};
                }

                sub STORE {
                    my ($self, $new_value) = @_;

                    print "Scalar was changed to $new_value\n";
                    $self->{value} = $new_value;
                }
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                package main;

                tie my $number, "LoggedScalar", 10;

                print "$number\n";   # Calls FETCH
                $number = 25;        # Calls STORE
                print "$number\n";   # Calls FETCH
            \end{perlcode}
        \item \textbf{Tied and untied}:  tied returns the underlying object or undef if the variable is not tied.
            \bigbreak \noindent 
            \begin{perlcode}
                my $object = tied($number);

                print $object->{value};
            \end{perlcode}
            \bigbreak \noindent 
            untie removes the connection:
            \bigbreak \noindent 
            \begin{perlcode}
            untie $number;
            \end{perlcode}
            \bigbreak \noindent 
            Afterward, \$number is once again an ordinary scalar.
            \bigbreak \noindent 
            A class can define UNTIE to perform cleanup:
            \bigbreak \noindent 
            \begin{perlcode}
                sub UNTIE {
                    my ($self, $reference_count) = @_;
                    print "Variable was untied\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            It can also define DESTROY, which runs when the underlying object is destroyed.

    \end{itemize}

    \unsect{Threads}
    \begin{itemize}
        \item \textbf{Threads}: Perl supports threads through the core threads module. However, Perl threads differ from lightweight POSIX threads: each Perl thread receives its own Perl interpreter and initially gets copies of the parent thread’s variables.
            \bigbreak \noindent 
            These are commonly called \textbf{interpreter threads}, or \textbf{ithreads}.
            \bigbreak \noindent 
            \begin{perlcode}
                use strict;
                use warnings;
                use threads;

                sub do_work {
                    my ($name) = @_;

                    print "Hello from $name\n";
                    return 42;
                }

                my $thread = threads->create(\&do_work, "worker");

                my $result = $thread->join();

                print "Worker returned: $result\n";
            \end{perlcode}
            \bigbreak \noindent 
            threads->create() starts a new thread and returns a thread object. The new thread executes do_work.
            \bigbreak \noindent 
            join() waits for the thread to finish and retrieves its return value.
            \bigbreak \noindent 
            You can also use an anonymous subroutine
            \bigbreak \noindent 
            \begin{perlcode}
                my $thread = threads->create(sub {
                    print "Running in another thread\n";
                    return 100;
                });

                my $result = $thread->join();
            \end{perlcode}
            \bigbreak \noindent 
            Ordinary variables are copied when the thread is created:
            \bigbreak \noindent 
            \begin{perlcode}
                use threads;

                my $number = 10;

                my $thread = threads->create(sub {
                    $number = 50;
                    print "Worker: $number\n";
                });

                $thread->join();

                print "Main: $number\n";
            \end{perlcode}
            \bigbreak \noindent 
            Changing \$number inside the worker does not change the parent thread’s copy.
        \item \textbf{Sharing variables}: Use threads::shared when multiple threads must access the same variable:
            \bigbreak \noindent 
            \begin{perlcode}
                use strict;
                use warnings;
                use threads;
                use threads::shared;

                my $counter :shared = 0;

                my @workers;

                for (1 .. 4) {
                    push @workers, threads->create(sub {
                        for (1 .. 1_000) {
                            lock($counter);
                            ++$counter;
                        }
                    });
                }

                $_->join() for @workers;

                print "Counter: $counter\n";
            \end{perlcode}
        \item \textbf{Locks}: A race condition occurs if multiple threads modify shared state concurrently. lock() gives the current thread exclusive access to a shared variable for the remainder of the enclosing scope:
            \bigbreak \noindent 
            \begin{perlcode}
                {
                    lock($counter);
                    ++$counter;
                }
            \end{perlcode}
            \bigbreak \noindent 
            The lock is automatically released when execution leaves the block. When locking multiple variables, always acquire the locks in a consistent order. Otherwise, two threads can wait on one another indefinitely—a condition known as deadlock.
            \bigbreak \noindent 
            Imagine we have Account A and Account B.
            \begin{itemize}
                \item Thread 1 wants to transfer \$100 from Account A to Account B. It locks Account A first, then tries to lock Account B.
                \item Thread 2 wants to transfer \$50 from Account B to Account A. It locks Account B first, then tries to lock Account A.
            \end{itemize}
            \begin{enumerate}
                \item Thread 1 acquires the lock for Account A.
                \item Thread 2 acquires the lock for Account B.
                \item Thread 1 attempts to acquire the lock for Account B and blocks ( because Thread 2 holds it).
                \item Thread 2 attempts to acquire the lock for Account A and blocks ( because Thread 1 holds it).
            \end{enumerate}
            Neither thread can proceed, and they will wait on each other indefinitely.
            \bigbreak \noindent 
            \textbf{Note:} Arrays and hashes can also be shared. For complicated shared structures, you may need shared\_clone():
            \bigbreak \noindent 
            shared\_clone is a helper function provided by the threads::shared module. It is designed to take a reference to a standard, non-shared data structure, perform a deep copy, and return a version of that structure that can safely be shared across different interpreter threads (ithreads).
            \bigbreak \noindent 
            If you try to assign a normal, unshared reference into a shared array or hash, Perl will throw an error like "Invalid value for shared scalar". shared\_clone solves this by recursively cloning and sharing every component of the structure.
        \item \textbf{Thread queues}: For producer-consumer programs, Thread::Queue is generally cleaner than manually sharing arrays and managing locks:
            \bigbreak \noindent 
            When writing multi-threaded Perl programs, multiple threads cannot safely read or write to a standard array at the same time without causing data corruption. Thread::Queue solves this problem by completely handling the underlying locks and synchronization, allowing any number of threads to push or pull data safely
            \begin{itemize}
                \item \textbf{Thread:}:Queue->new(): Creates a brand new, empty queue.
                \item \textbf{enqueue(LIST):} Adds one or more items to the end of the queue.
                \item \textbf{dequeue():} Removes and returns the item at the front of the queue. Crucially, if the queue is empty, dequeue() will pause (block) the execution of that thread until another thread enqueues something.
                \item \textbf{dequeue\_nb():} A non-blocking version of dequeue. If the queue is empty, it returns undef immediately instead of waiting.
                \item \textbf{pending():} Returns the number of items currently waiting in the queue.
                \item \textbf{end():} Tells the queue that no more items will be added. Any threads blocking on a dequeue() will unblock, and once the remaining items are consumed, dequeue() will return undef.
            \end{itemize}
            \bigbreak \noindent 
            The most common use case for Thread::Queue is a producer-consumer pattern, where a main script splits tasks up and feeds them to worker threads.
            \bigbreak \noindent 
            \begin{perlcode}
                use strict;
                use warnings;
                use threads;
                use Thread::Queue;

                my $task_queue = Thread::Queue->new();

                # Create worker threads
                my @workers;
                for (1..3) {
                    push @workers, threads->create(\&worker_logic);
                }

                # Feed data into the queue (The Producer)
                for my $job_id (1..10) {
                    print "Main: Enqueuing job $job_id\n";
                    $task_queue->enqueue($job_id);
                }

                # Signal workers that no more data is coming
                $task_queue->end();

                # Wait for all threads to finish up
                $_->join() for @workers;
                print "Main: All jobs completed!\n";


                # --- Worker Subroutine ---
                sub worker_logic {
                    my $tid = threads->tid(); # Get current thread ID

                    # dequeue() will automatically return undef after $task_queue->end() 
                    # AND the queue becomes completely empty.
                    while (defined(my $job = $task_queue->dequeue())) {
                        print "Worker $tid: Processing job $job\n";
                        sleep(1); # Simulate processing time
                    }

                    print "Worker $tid: Shutting down.\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            Enqueuing undef causes your program to hang because Perl's enqueue() method discards undef values instead of adding them to the queue.
            \bigbreak \noindent 
            You do not need to write your own locks because Thread::Queue automatically wraps all of its internal data manipulations in thread-safe locks using Perl’s native threads::shared mechanisms. Every time you call a method like enqueue or dequeue, the module handles the complex locking logic for you.
            \bigbreak \noindent 
            When the main thread adds an item, the module executes these precise steps:
            \begin{enumerate}
                \item \textbf{Acquires an Internal Lock:} It locks the queue's internal storage array so no other thread can read or write to it at that exact microsecond.
                \item \textbf{Filters the Input:} It checks the data. If it is undef, it drops it. If it is a complex data structure (like a hash reference), it clones it so it can safely exist in shared memory.
                \item \textbf{Pushes the Data:} It appends the item to the end of the array.
                \item \textbf{Signals Waiting Threads:} It issues a cond\_signal() (conditional signal). This acts like an alarm clock telling any sleeping worker threads, "Hey, data just arrived!"
                \item \textbf{Releases the Lock:} It unlocks the array so other threads can use it.
            \end{enumerate}
            When a worker thread asks for a job, the module performs this sequence:
            \begin{enumerate}
                \item Acquires an Internal Lock: It locks the internal array to ensure exclusive access.
                \item Checks for Data:
                \begin{itemize}
                    \item If data exists: It shifts the first item off the front of the array, releases the lock, and returns the item to the worker.
                    \item If the queue is empty: It places the worker thread into a specialized sleep state called cond\_wait(). Crucially, entering this sleep state temporarily releases the lock so other threads aren't blocked from adding data.
                \end{itemize}
                \item \textbf{Wakes Up:} When an enqueue() triggers the cond\_signal(), the sleeping worker wakes up, re-acquires the lock, grabs the newly arrived item, releases the lock, and goes to work.
            \end{enumerate}
            In multi-threaded programming, you can queue almost anything, but the golden rule is to queue the instructions or identifiers for the work, rather than the massive data objects themselves.
            \bigbreak \noindent 
            \textbf{Note:} While the queue itself is thread-safe, it only protects the data while it is inside the queue.  The moment a worker thread dequeues an item and uses it to modify a completely separate shared global variable, you lose all protection.
        \item \textbf{Join vs detach}: A joinable thread retains some resources until another thread calls join(). A detached thread runs independently, and its return value cannot be collected
            \bigbreak \noindent 
            \begin{perlcode}
            my $result = $thread->join();
            $thread->detach();
            \end{perlcode}
            Use join() when you need the result or must ensure the work completes. Use detach() only for genuinely independent background work.
        \item \textbf{Identifying threads}: 
            \bigbreak \noindent 
            \begin{perlcode}
                my $id = threads->tid();
                print "Current thread ID: $id\n"; 
            \end{perlcode}
            \bigbreak \noindent 
            The original thread has ID 0. Worker threads receive other numeric IDs.
            \bigbreak \noindent 
            You can inspect existing threads with 
            \bigbreak \noindent 
            \begin{perlcode}
                my @joinable = threads->list(threads::joinable);
                my @running  = threads->list(threads::running);
            \end{perlcode}
            \bigbreak \noindent 
            A running thread is actively executing code, while a joinable thread is an active or finished thread whose resources have not yet been cleaned up by a join() or detach() call. 
        \item \textbf{Zombie threads}: If you do not join or detach a thread, you create what is commonly known as a zombie thread, causing resource leaks and potentially causing your program to crash.
            \bigbreak \noindent 
            When a thread finishes executing its function, its internal stack memory, register states, and exit status are not automatically freed if it is joinable.
            \begin{itemize}
                \item The operating system keeps these structures alive because it assumes the parent thread will eventually call join() to read the exit value.
                \item If you continuously spawn threads without joining or detaching them, you will rapidly deplete the system's memory allocation and file descriptors.
            \end{itemize}
        \item \textbf{Error handling}: If a thread terminates with die, join() reports the failure. It is usually clearer to handle errors inside the thread:
            \bigbreak \noindent 
            \begin{perlcode}
                my $thread = threads->create(sub {
                    my $result = eval {
                        perform_operation();
                    };

                    return {
                        result => $result,
                        error  => $@,
                    };
                });

                my $outcome = $thread->join();

                die $outcome->{error} if $outcome->{error};
            \end{perlcode}






    \end{itemize}

    \unsect{System interaction}
    \begin{itemize}
        \item \textbf{system()}: The system() function allows an external command to be executed. This command will inherit Perl’s standard filehandles (STDIN, STDOUT and STDERR) and have control of the console until it terminates. This means that system() can be used to launch interactive commands such as editors if desired. Perl will wait for the command specified to terminate before continuing:         
            \bigbreak \noindent 
            \begin{perlcode}
                # Open a file for the user to edit.
                system(’vi somefile.txt’); # Or ’notepad somefile.txt’

                # Read the contents of the file once the user has finished.
                open(my $input_fh, ’<’, ’somefile.txt’) or die "$!";
            \end{perlcode}
            \bigbreak \noindent 
            The exec() function works in a similar way, but on success your program is replaced with the command specified. This means that exec() never returns on success. The exec() function is most useful when writing wrapper scripts that wish to establish a certain state before executing another program.
            \bigbreak \noindent 
            If the command specified by system() could not be run the error message will be available via the special variable \$!. This value is not set if the command can be run but fails during runtime. The return status of the command can be found in the special variable \$?, which is also the return value of system(). This value is a 16-bit status word which needs to be unpacked to be useful, as demonstrated in the example below.
            \bigbreak \noindent 
            \begin{perlcode}
                system("/path/to/some/command");
                if ($?) { # A non-zero exit code means failure
                    # -1 means the program didn’t even start!

                    if($? == -1) {
                        print "Failed to run program: $!\n";
                    } 

                    else {
                        print "The exit value was: " . ($? >> 8) . "\n";
                        print "The signal number that terminated the program was: "
                                . ($? & 127) . "\n";
                        print "The program dumped core.\n" if $? & 128;
                    }
                }
            \end{perlcode}
        \item \textbf{Security concerns}: Just like open the traditional form of calling system and exec have security issues due to shell expansion. For example consider the following code:
            \bigbreak \noindent 
            \begin{perlcode}
                print "Please give me a file you want to see: ";

                my $filename = <>; # lets pretend: $filename="fred; rm -rf /home/pjf;"

                chomp($filename);
                system("cat $filename");
            \end{perlcode}
            \bigbreak \noindent 
            In this case, due to shell expansion, the shell will receive the commands:
            \bigbreak \noindent 
            \begin{perlcode}
            cat fred
            rm -rf /home/pjf
            \end{perlcode}
            \bigbreak \noindent 
            and if our program had sufficient permissions to delete pjf’s home directory, it would.
            \bigbreak \noindent 
            As a result, there is another, safer, form of system and exec that bypasses the shell. If you give system or exec a list it assumes that the first element is the command to execute, and every other element is an argument to that command. These arguments are not passed to the shell, and so shell expansion will not occur. So:
            \bigbreak \noindent 
            \begin{perlcode}
            system(’cat’, ’*.txt’);
            \end{perlcode}
            \bigbreak \noindent 
            will give the "*.txt" filename to cat rather than all files with a .txt extension. This is essential in cases like the above where the command may be passed in from a user. In this case, if the file "*.txt" does not exist then we’ll receive an non-zero return code. Exec fails and returns false only if the command (in this case cat) does not exist. If the file does not exist, the user will receive cat’s error message
            \bigbreak \noindent 
            It’s always possible to use Perl’s glob function to expand filenames for us, without shell intervention:
            \bigbreak \noindent 
            \begin{perlcode}
            system("cat", "*.txt");
            \end{perlcode}
        \item \textbf{IPC::System::Simple}: The IPC::System::Simple module (available from the CPAN) takes the hard work out of running shell commands:
            \bigbreak \noindent 
            \begin{perlcode}
                use IPC::System::Simple qw(run);

                run("some_command");
            \end{perlcode}
            \bigbreak \noindent 
            The run function will execute the command provided and check the result. If the command fails to start, dies from a signal, dumps core, or returns a non-zero exit status, then IPC::System::Simple will throw an exception. Unless you take steps to prevent it, a failure from this command will cause your program to die with an error. If you want to capture the error, you can do so:
            \bigbreak \noindent 
            \begin{perlcode}
                # The ’eval’ block allows us to capture errors, which
                # are then placed in $@. If any of the commands below
                # fail, the ’eval’ is exited immediately. This means if
                # we fail to backup the files, we won’t delete them.

                eval {
                    run(’backup_files’);
                    run(’delete_files’);
                };

                if ($@) {
                    warn "Error in running commands: $@\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            You can also use IPC::System::Simple to execute commands that can return a range of acceptable exit values:
            \bigbreak \noindent 
            \begin{perlcode}
            use IPC::System::Simple qw(run);

            # Run a command, insisting it return 0, 1 or 2:
            run( [0,1,2], "some_command");

            # Run a command and capture its exit value:
            my $exit_value = run( [0,1,2], "some_command");

            # Specify return values using ’..’ notation:
            my $exit_value = run( [0..2], "some_command");
            \end{perlcode}
            \bigbreak \noindent 
            Just like regular system, the run command uses the standard shell when running a single command, or invokes the command directly when called in a multiple argument fashion:
        \item \textbf{Backticks}: A new set of quotes, called backticks, can be used to interpolate variables then run the resultant string as a shell command. The output of that command can then be printed, assigned, and so forth.
            \bigbreak \noindent 
            Just as the q() and qq() functions can be used to emulate single and double quotes and save you from having to escape quotes that appear within a string, the equivalent function qx() can be used to emulate backticks.
            \bigbreak \noindent 
            Backticks are different to the system() command, in that they capture the output of the command they execute, as opposed to passing it through to the user.
            \bigbreak \noindent 
            When called in a scalar context backticks return the output of the command they execute as a string with possibly embedded newlines. When called in a list context, the output is returned as a list with each separate line of output being a new list element.
            \bigbreak \noindent 
            The return status of commands called by using backticks can be determined by examining \$? in the same way as the system() example above.
        \item \textbf{Tainted input}: Perl’s -T flag can be used to check for unsafe user inputs.
            \bigbreak \noindent 
            \begin{perlcode}
            #!/usr/bin/perl -Tw
            \end{perlcode}
            \bigbreak \noindent 
            -T stands for "taint checking". Data input by the user is considered "tainted" and until it has been modified by the script, may not be used to perform shell commands or system interactions of any kind. This includes system interactions such as open(), chmod(), and any other built-in Perl function which interacts with the operating system.
            \bigbreak \noindent 
            The only thing that will clear tainting is referencing substrings from a regexp match. Here’s an example.
            \bigbreak \noindent 
            \begin{perlcode}
                #!/usr/bin/perl -Tw
                use strict;

                $ENV{PATH} = "/bin:/usr/bin"; # Taint requires we set our path.

                print "Who do you want to finger?\n";
                my $username = <STDIN>;
                chomp($username);

                # Check $username to make sure it’s clean, then finger.
                if ( $username =~ /^(\w{1,8})$/ ) {
                    # $1 is the contents of the first set of
                    # parentheses in the regexp.

                    print qx(finger $1);
                } 

                else {
                    print "That was not a valid username!\n";
                }
            \end{perlcode}
            \bigbreak \noindent 
            You can also untaint data by capturing the match in a list context.
            \bigbreak \noindent 
            If you’ve been calling your Perl program from the command line with perl program.pl you’ll be told that you’re turning taint checking on too late, even if you’ve put it in your shebang line.
            \bigbreak \noindent 
            This is because Perl wants to know that you want to use taint checking as soon as possible. The way to fix this is to include the -T option in your call, so: 
            \bigbreak \noindent 
            \begin{perlcode}
                perl -T program.pl.
            \end{perlcode}
            \bigbreak \noindent 
            Under Perl 5.8.0 and above, there is also the -t switch, which causes tainted operations to generate warnings instead of errors. This is no substitute for real taint checking, but can be useful if you’re trying to lock down legacy code and see which areas require attention.
        \item \textbf{Safe.pm}: For greater security when using unknown (and possibly hostile) code, or for writing code which adheres to strict standards about what it’s allowed to do, there is the Safe module. This module allows the creation of compartments in which Perl code can be evaluated. These compartments allow you to define explicitly what the code run within them may and may not do. For example, you may deny access to the file system so that the code may not read or write to files. Or you may only permit the code to use certain operators such that it may add and subtract but not divide, for example. Attempts by the code to perform forbidden tasks result in a compilation error at compile time and a fatal error at run time.


    \end{itemize}

    \unsect{Idioms}
    \begin{itemize}
        \item \textbf{Representation of true and false}: 
            Perl does not have a native true or false keyword. Instead, it determines a value's truth by evaluating what it is.
            \bigbreak \noindent 
            Only a few specific values are considered false in Perl:
            \begin{itemize}
                \item The number 0 (or 0.0)
                \item The string "0"
                \item The empty string ""
                \item undef (undefined)
                \item An empty list ()
            \end{itemize}
            Everything else is true. When you use a single logical NOT (!), Perl evaluates the operand's truth and returns an absolute boolean result.
            \begin{itemize}
                \item If you pass it something false, it returns 1 (Perl's standard "true" value).
                \item If you pass it something true, it must return a "false" value. By language design, Perl's logical operators return the empty string ("") to represent false.
            \end{itemize}

    \end{itemize}

    \subsection{Secret Operators}
    \begin{itemize}
        \item \textbf{Bare number flip-flop}: Print lines 5 through 10 of a file:
            \bigbreak \noindent 
            \begin{perlcode}
            perl -ne 'print if 5..10'
            \end{perlcode}
            \bigbreak \noindent 
            When the flip-flop operator .. sees a bare integer on either side, it silently compares that integer against \$., the current input line number. The expression 5 .. 10 is really \$. == 5 .. \$. == 10.
            \bigbreak \noindent 
            In list context, .. is the range operator:
            \bigbreak \noindent 
            \begin{perlcode}
            my @nums = (1..5)
            \end{perlcode}
            \bigbreak \noindent 
            In scalar context (like inside an if condition), it becomes the \textbf{flip-flop operator}. It remembers state between calls. It starts in the OFF state. When the left condition becomes true, it flips ON. When the right condition becomes true, it flops back OFF.
            \bigbreak \noindent 
            \begin{perlcode}
                for my $i (0..9) {
                    $i > 2 .. $i > 8 
                        ? print "${i}\n" 
                        : print "";

                    ${i}++;
                }

                =pod 
                3
                4
                5
                6
                7
                8
                9
                =cut
            \end{perlcode}
            \bigbreak \noindent 
            When you put a bare number where the flip-flop expects a condition, Perl doesn't treat it as a boolean. It compares it to \$..

        
        \item \textbf{Eskimo greeting (Butterfly operator)}: Count the lines in a file:
            \bigbreak \noindent 
            \begin{perlcode}
                perl -lne '}{ print $.'
            \end{perlcode}
            \bigbreak \noindent 
            Those two braces break out of the implicit while loop that -n creates, and start a new block that runs exactly once, after all input has been processed. An END block without typing END.
            \bigbreak \noindent 
            Every line of input becomes \$\_, your code runs, next line. The -p flag does the same thing but adds print at the end of each iteration.
            \bigbreak \noindent 
            Simple enough. But what if you want to do something AFTER all lines are processed? You could use an END block
            \bigbreak \noindent 
            \begin{perlcode}
                perl -ne '$sum += $_; END { print $sum }' numbers.txt
            \end{perlcode}
            \bigbreak \noindent 
            Or you could use two braces and save yourself some typing.
            \bigbreak \noindent 
            \begin{perlcode}
                perl -ne '$sum += $_; }{ print $sum' numbers.txt
            \end{perlcode}
            \bigbreak \noindent 
            Perl wraps it into:
            \bigbreak \noindent 
            \begin{perlcode}
                while (<>)
                {
                    $sum += $_;
                }
                {
                    print $sum
                }
            \end{perlcode}
        \item \textbf{Maori Farewell}: The butterfly operator gives you an END block in one-liners. But what about BEGIN? What if you need code to run BEFORE the loop starts?
            \bigbreak \noindent 
            \begin{perlcode}
            -M5;
            \end{perlcode}
            \bigbreak \noindent 
            Everything after the semicolon runs before your main code. Normally -M loads a module, but with -M5;, something different happens.
            \bigbreak \noindent 
            -M5 means
            \bigbreak \noindent 
            \begin{perlcode}
            use 5;          # Require Perl version 5 (always true)
            \end{perlcode}
            \bigbreak \noindent 
            The semicolon separates the version requirement from arbitrary code. Since we're all running Perl 5+, the version check passes silently.
            \bigbreak \noindent 
            What comes after the semicolon runs at compile time, before the -n or -p loop even starts. It's not quite a real BEGIN block, but it acts like one for practical purposes.
            \bigbreak \noindent 
            \begin{perlcode}
            perl -M'5;print scalar localtime, "\n"' -ne 'print if /error/i' log.txt
            \end{perlcode}
        \item \textbf{Triple dot flip flop}: The flip-flop in its natural habitat:
            \bigbreak \noindent 
            \begin{perlcode}
                while (<DATA>)
                {
                    print if m~START~ .. m~END~;
                }

                __DATA__
                noise
                START
                grab this
                and this
                END
                more noise

                =pod
                    START
                    grab this
                    and this
                    END
                =cut
            \end{perlcode}
            \bigbreak \noindent 
            The .. flips ON when it sees START. It stays on, returning true for every line. When it sees END, it returns true one last time and flips OFF. Simple. For 95\% of use cases, that's all you need to know. But the remaining 5\% is where things get interesting.
            \bigbreak \noindent 
            .. checks the right-hand condition on the same line the left-hand condition triggers. ... waits until the next line to start checking the right-hand condition.
            \begin{itemize}
                \item ..   Can flip ON and OFF on the same line
                \item ...  Guarantees at least two evaluations (the trigger line plus the next)
            \end{itemize}
            This only matters when both conditions can match the same line
        \item \textbf{Yada Yada}: The yada yada operator. Perl's way of saying "I haven't written this part yet."
            \bigbreak \noindent 
            \begin{perlcode}
                sub fn {
                    ...
                }
            \end{perlcode}
            \bigbreak \noindent 
            Compiles and runs, but fails if you try to call it.
        \item \textbf{Venus operator}: Force numeric context with
            \bigbreak \noindent 
            \begin{perlcode}
            0+
            \end{perlcode}
            \bigbreak \noindent 
            The Venus operator. Named because it looks like the astronomical symbol for Venus
            \bigbreak \noindent 
            \begin{perlcode}
                my $str = "42";
                my $num = 0 + $str;
            \end{perlcode}
            \bigbreak \noindent 
            Now \$num is numerically 42, not the string "42". Perl usually handles string/number conversion automatically. But sometimes you need to force it


        \item \textbf{Goatse operator =()=}: Used to force an expression on its right-hand side into a list context while evaluating the entire assignment in a scalar context. It returns the number of items generated by the right-hand side expression
            \bigbreak \noindent 
            It is most frequently used to count regex matches in global matching mode (/g) without storing all the matched text in memory:
            \bigbreak \noindent 
            \begin{perlcode}
                my $text = "cat dog cat bird cat";
                my $count = () = $text =~ /cat/g; 
                print $count; # Outputs 3
            \end{perlcode}
        \item \textbf{Flathead}: Forces scalar context, interpolating a single value.
            \begin{perlcode}
                ${\( EXPRESSION )}

                ( EXPRESSION )     Evaluate expression in scalar context
                \( ... )           Create a reference to that scalar value
                ${ ... }           Dereference it for interpolation
            \end{perlcode}
        \item \textbf{Babycart}: Five characters that let you interpolate ANY expression in a string.
            \bigbreak \noindent 
            \begin{perlcode}
                @{[ ]}
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                my $x = 5;
                my $y = 3;

                print "Sum: @{[ $x + $y ]}";    # Sum: 8
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                @{[ EXPRESSION ]}

                [ EXPRESSION ]     Anonymous array reference containing EXPRESSION
                @{ ... }           Dereference that array reference
            \end{perlcode}
            \bigbreak \noindent 
            The expression is evaluated in list context, wrapped in an anonymous array, then immediately dereferenced for interpolation.
        \item \textbf{Bang bang}: The bang bang operator forces any scalar value into a strict boolean 1 or empty string "" (which Perl treats as false). It is simply two consecutive logical NOT (!) operators.
            \bigbreak \noindent 
            The first ! evaluates the value and flips its truthiness to a strict boolean (making a true value "" and a false value 1). The second ! flips it back.
            \bigbreak \noindent 
            Perl doesn't have a dedicated boolean type. If a function returns an object, a string, or a number on success, using !! cleans up the data so it only returns a clean 1 (true) or "" (false).
            \bigbreak \noindent 
            \begin{perlcode}
                my $user_input = "Hello"; 

                my $pure_boolean = !!$user_input; 
                print $pure_boolean; # Outputs 1
            \end{perlcode}
        \item \textbf{Enterprise operator}: Conditional list elements. You want an item in a list only if some condition is true:
            \bigbreak \noindent 
            \begin{perlcode}
                ()x!!
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                my @args = (
                    '--verbose',
                    ('--debug') x !!$debug,
                    '--output', $file,
                );
            \end{perlcode}
        \item \textbf{Double diamond}: The diamond operator has a problem. A security problem.
            \bigbreak \noindent 
            \begin{perlcode}
            perl script.pl 'ls |'
            \end{perlcode}
            \bigbreak \noindent 
            That doesn't read a file called "ls |". It executes ls and reads its output. Oops.
            \bigbreak \noindent 
            The regular diamond uses two-argument open internally:
            \bigbreak \noindent 
            \begin{perlcode}
                while (<>) # open(ARGV, $ARGV[0])
            \end{perlcode}
            \bigbreak \noindent 
            The triple diamond uses three-argument open
            \bigbreak \noindent 
            \begin{perlcode}
                while (<<>>) # open(ARGV, "<", $ARGV[0])
            \end{perlcode}



    \end{itemize}

    \unsect{Standard functions}
    \begin{itemize}
        \item \textbf{Map}: The Perl map function transforms a list of values into a new list of values by running a block of code or an expression on each element.
            \bigbreak \noindent 
            You can use map with either a block of code enclosed in curly braces or a simple expression followed by a comma:
            \bigbreak \noindent 
            \begin{perlcode}
            my @new_list = map { BLOCK } @old_list;
            my @new_list = map EXPR, @old_list;
            \end{perlcode}
        \item \textbf{Grep}: grep function acts as a list filter. It evaluates a block of code or an expression for every element in a list, setting the default variable \$\_ to each element one by one. It then returns only the elements for which the condition evaluates to true.
            \bigbreak \noindent 
            \begin{perlcode}
            my @results = grep { CONDITION } @list;
            my @results = grep CONDITION, @list;
            \end{perlcode}
            \bigbreak \noindent 
            \begin{perlcode}
                my @fruits = ('Apple', 'Banana', 'Avocado', 'Cherry');

                # Find fruits starting with 'A'
                my @a_fruits = grep { /^A/ } @fruits; 
            \end{perlcode}
        \item \textbf{List::Util::reduce}: The reduce function steps through a list two elements at a time, accumulating a single result.
            \bigbreak \noindent 
            It registers the accumulator as \$a and the current element as \$b.
            \bigbreak \noindent 
            \begin{perlcode}
            use List::Util qw(reduce)
            my $res = reduce { BLOCK } @list;

            my $sum = reduce { $a + $b } @numbers;
            my $max = reduce { $a > $b ? $a : $b } @numbers;
            \end{perlcode}
        \item \textbf{Quotemeta}: In Perl, the quotemeta function returns a string with all non-word characters escaped with a backslash. It explicitly targets any ASCII character not matching the /[A-Za-z_0-9]/ regular expression.
            \bigbreak \noindent 
            In double-quoted strings or directly inside regular expressions, quotemeta is internally invoked using the \string\\;Q escape sequence. The escaping continues until it hits a \string\\;E sequence or reaches the end of the string
            \bigbreak \noindent 
            \begin{perlcode}
                my $literal = "hello.world*";

                # Approach 1: Using the function
                my $pattern1 = quotemeta($literal); # Returns "hello\.world\*"

                # Approach 2: Using \Q and \E in a regex match
                if ($text =~ /\Q$literal\E/) {
                    print "Matched literally!";
                }
            \end{perlcode}
            \bigbreak \noindent 
            \string\\;Q and \string\\;E are used to escape (disable) regex metacharacters, forcing the regex engine to treat everything between them as a literal string.
            \begin{itemize}
                \item \string\\;Q starts the literal quotation (it stands for "quotemeta").
                \item \string\\;E ends the quotation block. If you omit \string\\;E, the literal matching applies until the very end of the regex pattern
            \end{itemize}


    \end{itemize}
